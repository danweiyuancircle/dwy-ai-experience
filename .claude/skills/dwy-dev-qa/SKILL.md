# 开发完成后质量保障流程

功能开发完成后，必须按以下 9 步流程逐步执行，确保代码质量、测试覆盖和文档同步。**不可跳步，不可调换顺序。**

## 流程总览

```
功能完成 → 构建验证 → 写测试 → 跑测试 → Code Review → 修复问题 → 性能优化 → 文档同步 → 集成测试 → 输出报告
```

## 第 1 步：构建验证

确认代码能编译通过，没有语法错误或类型错误。

```bash
# 前端
pnpm build:eui    # 或对应包的构建命令
# 后端
cd backend && ruff check src/
```

**不通过 → 修复编译错误，不进入下一步。**

## 第 2 步：编写测试用例

为本次新增/修改的代码编写测试：

- 新组件：至少覆盖 props 渲染、事件触发、slot 内容
- 新函数：覆盖正常输入、边界条件、异常输入
- Bug 修复：先写复现 bug 的测试用例，确认测试失败，再确认修复后通过
- 只测新增/修改的部分，不要给未改动的代码补测试

## 第 3 步：运行测试

```bash
# 前端
cd frontend/eui && pnpm vitest run
cd frontend/ekit && pnpm vitest run
# 后端
pnpm -w run test:eapi
```

**有失败 → 修复代码或测试，不进入下一步。**

## 第 4 步：Code Review

审查本次所有变更（代码 + 测试），检查：

- [ ] 逻辑正确性：是否有遗漏的边界条件、竞态风险
- [ ] 安全性：是否有 XSS、注入、硬编码凭证等问题
- [ ] 向后兼容：已有 API 是否被破坏（props 重命名/删除、函数签名变更）
- [ ] 代码风格：是否符合项目规范（Vue/Python/TypeScript）
- [ ] 测试质量：测试是否真正验证了功能，而不是走过场

输出 Review 发现的问题清单。

## 第 5 步：修复 Review 问题

逐条修复第 4 步发现的问题。每修复一条，重新跑一次相关测试确认没有回归。

**有未修复的问题 → 不进入下一步。**

## 第 6 步：性能优化

审查本次变更的性能影响：

- [ ] 是否有不必要的重复计算（应该用 computed 的用了 method）
- [ ] 是否有大列表没有虚拟滚动或懒加载
- [ ] 是否有 N+1 查询或未加索引的数据库查询
- [ ] 是否有不必要的深拷贝或大对象序列化
- [ ] Vue 组件：是否有不必要的响应式依赖触发重渲染

如果发现优化点：
1. 实施优化
2. 跑测试确认没有回归
3. 如果发现了通用的性能规范不在当前项目的 CLAUDE.md 或 rules 中，更新文档

## 第 7 步：文档同步

调用 `dwy-docs-check` skill 执行全量文档完整性检查（7 项），覆盖预览网站全部 5 个模块 + SKILL.md + CLAUDE.md。

发现问题自动修复，修复后重跑确认全绿。

## 第 8 步：集成测试

运行全量测试套件，确认无回归：

```bash
# 全部前端测试
cd frontend/eui && pnpm vitest run
cd frontend/ekit && pnpm vitest run
# 全部后端测试
pnpm -w run test:eapi
# 构建验证
pnpm build:eui && pnpm build:ekit
```

**任何失败 → 回到第 5 步修复。**

## 第 9 步：输出报告

向用户输出以下报告，等待审查确认：

```
## 质量保障报告

### 变更概要
- 涉及文件：X 个
- 新增/修改行数：+X / -X

### 测试结果
- 单元测试：X 通过 / X 失败
- 集成测试：全量 X 用例通过

### Code Review
- 发现问题：X 条
- 已修复：X 条
- 遗留：0 条

### 性能优化
- 优化项：（列出具体优化点，或"无需优化"）

### 文档同步
- 更新了：（列出更新的文件，或"无需更新"）

### 待用户确认
- [ ] 确认可以提交
```

**等用户回复确认后才能执行 git commit。**
