# Agent 并行模式速查表

## 一、任务级并行模式

| 模式 | 场景 | 要点 |
|------|------|------|
| 批量创建 | N 个独立组件/页面/测试/demo | 每 Agent 用 worktree,prompt 含 API 说明和规范 |
| 研究 → 实现 | 先探索代码再动手 | 阶段 1 并行派 Explore Agent;阶段 2 主线程或单 Agent 实现;阶段 3 并行验证 |
| 多模块同步改 | 一个功能涉及多模块(如给所有 API 加分页) | 每模块 1 Agent,worktree 隔离,统一修改规范 |
| 前后端同步 | 接口契约已定 | 前后端各 1 Agent,共享接口契约定义 |

## 二、步骤级并行场景

**信息收集**(任务开始前):同一消息发 Grep + Glob + Read + Agent(Explore)。

**验证**(修改完成后):同一消息发 Bash × N(测试 / lint / 类型检查 / 构建)。

**文档补充**(代码完成后):同一消息发 Agent × N(写测试 / 更文档 / 改 changelog)。

## 三、反模式

| 反模式 | 问题 | 正确做法 |
|--------|------|---------|
| 多 Agent 改同一文件 | 冲突、覆盖 | 串行 或 worktree 分文件 |
| 无上下文的 Agent prompt | 产出质量差 | prompt 必须自包含 |
| 链式依赖硬并行 | B 需要 A 的输出却并行 | 识别依赖,串行执行 |
| 单批 ≥6 个 Agent | 难管理、context 爆炸 | 单批 ≤5 个,分批执行 |

## 四、Worktree 使用

**用**:多 Agent 各改不同文件 / 修改可能与主工作区冲突 / 需保持主工作区干净。
**不用**:纯只读 Explore / 步骤级工具调用(Grep/Glob/Read/Bash) / 单 Agent 无冲突。
