# Agent 团队并行执行规则

## 一、可并行性评估

| 条件 | 判定 |
|------|------|
| 任务可拆为 2+ 个**无依赖**子任务 | 任务级并行 |
| 单个任务内有 2+ 个**独立步骤** | 步骤级并行 |
| 单一线性流程或子任务有依赖 | 不并行,串行执行 |

## 二、风险分级

| 等级 | 场景 | 执行方式 |
|------|------|---------|
| 低 | 只读研究、新建独立文件、lint/format、查外部文档 | 直接并行,完成后汇报 |
| 中 | 修改已有文件、加/升依赖、改构建/路由配置 | 展示拆分计划 → 用户确认 → 并行执行 |
| 高 | 删文件/代码、改核心模块(数据库/认证/支付)、架构重构、git rebase/merge/force push | 详细计划 + 影响分析 → 确认 → 执行 → 强制 review |

## 三、派遣协议

**任务级并行**:独立子任务拆给多个 Agent,**同一条消息**中派出(保证真正并行);修改文件的 Agent 用 `isolation: "worktree"`。

**步骤级并行**:识别无依赖的步骤,在同一条消息中发起多个工具调用(Agent / Bash / Grep / Glob 均可)。

**Agent prompt 必须自包含**,含:目标、上下文、操作范围、需遵循的规则、期望产出形式。禁止写"基于你的研究结果去做"这种模糊指令。

## 四、Review 闭环

**触发**:高风险任务完成后、≥3 个 Agent 并行修改代码后、用户明确要求时。
**跳过**:纯只读研究、单个低风险文件创建。

**流程**:启动 `superpowers:code-reviewer` → 有问题直接修 → 再 review(最多 2 轮)→ 仍有问题报给用户。

## 五、禁止事项

禁止派 Agent 做需用户交互的操作;禁止多 Agent 改同一文件(用 worktree 或串行);禁止 Agent prompt 省略上下文;禁止跳过风险评估直接并行;禁止忽略 Agent 失败结果,必须处理或报告。
