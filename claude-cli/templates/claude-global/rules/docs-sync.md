# 文档同步规则

代码变更时，必须同步更新所有关联文档。不允许只改代码不更新文档。

## 核心原则

**代码和文档是一个整体。** 如果一次变更修改了对外可见的 API（props、函数签名、导出类型、命令行参数等），那么描述该 API 的文档必须在同一个 commit 中更新。

## 检查清单

完成代码变更后，逐项确认：

1. **Skills / 速查文档** — 是否有 SKILL.md 或类似的 AI 速查文档描述了被修改的 API？如果有，更新对应条目。
2. **示例 / Demo 页面** — 新增的功能是否有对应的交互演示？如果没有，补充 demo。
3. **导航 / 搜索索引** — 新增的页面或组件是否已注册到路由、侧边栏、搜索索引？
4. **项目 CLAUDE.md** — 模块结构（新增/删除/重命名包或模块）、构建命令、测试命令是否变化？如果是，更新 CLAUDE.md。
5. **版本号** — 变更是否对外可见？如果是，更新 package.json / pyproject.toml 版本号。

## 提交规范

- 文档更新应与代码变更在**同一个 commit** 中
- 遗漏后发现，立即补一个 `docs: sync xxx` 的 commit
- 纯文档更新用 `docs:` 前缀，代码+文档混合用 `feat:` / `fix:`
