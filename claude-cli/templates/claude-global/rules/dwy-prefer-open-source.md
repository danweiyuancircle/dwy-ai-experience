# 优先使用成熟开源方案

开发新功能时，优先选用成熟的开源项目/库，而不是手写实现。只有在确认没有合适的开源方案时，才自行实现。

## 决策流程

```
需要某项功能
  → 1. 搜索是否有成熟的开源库（npm/PyPI/GitHub stars > 1k、近期有维护）
    → 有：评估是否适配当前技术栈（Vue 3 / FastAPI / Node.js）
      → 适配：直接使用，不重复造轮子
      → 不适配：寻找替代方案
    → 没有合适的：自行实现，但在代码注释中说明为什么没用现成方案
```

## 强制规则

- **禁止**手写已有成熟方案的功能：日期处理(dayjs/date-fns)、HTTP 请求(axios)、表单校验(zod/vee-validate)、状态管理(pinia)、图表(echarts/chart.js)、富文本(tiptap/quill)、拖拽(vuedraggable/dnd-kit)、虚拟滚动(@tanstack/virtual)、Markdown 渲染(markdown-it)、模糊搜索(fuse.js)
- **禁止**手写加密/哈希/JWT 算法，必须使用 bcrypt/jose/crypto 等标准库
- 选用开源库时，优先选择：项目已在用的依赖 > 社区主流方案 > 小众但适合的方案

## 例外情况

以下情况允许自行实现：
- 功能极其简单（< 20 行），引入一个库反而增加复杂度
- 开源库有严重的安全漏洞或已停止维护
- 开源库的依赖体积过大，与需求不成比例
- 项目有特殊定制需求，开源库无法满足且改造成本高于自建
