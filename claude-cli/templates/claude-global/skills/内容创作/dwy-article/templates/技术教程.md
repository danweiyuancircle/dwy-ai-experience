# 技术教程模板

定位：**照着零跳步就能复现**。步骤必须齐、命令必须完整。但省掉原理和术语科普——不解释「为什么」，只给「怎么做」，保持精简。

固定锚点，按顺序：

```
# 标题：直接说清做什么（如「用 frps 把群晖 NAS 暴露到公网」）

[开篇] 1-2 句：要解决什么问题 / 什么场景用得上。不铺垫、不讲原理。

## 开始前准备
把前置条件一次性列全，读者照着先备齐：系统 / 软件版本 / 下载链接 / 需要的账号 / 要放行的端口 / 依赖。漏一项，读者就会卡在中途。

## 步骤 1 · 这步在干嘛
先一句说这步做什么，再给**完整、可直接复制**的命令或操作：
- 命令不截断、不省略，含真实路径和文件名
- 凡是要读者替换的，用占位符写清并标注「改成你自己的 X」（如 `serverAddr = "你的公网IP"`）
- 给出预期结果：看到什么输出 / 什么现象，才算这步成了
## 步骤 2 · 下一步在干嘛
同上。**零跳步**——不能出现「配置一下 xxx」这种含糊带过，每一步都要能照着做出来。

（步骤按实际数量往下排）

## 踩坑提醒
把坑单独成一节，每个坑写清三件事：现象（报什么错 / 什么表现）→ 原因 → 怎么解。让读者对照自己卡在哪。

## 验证
怎么确认整套通了——一条命令或一个现象。

[收尾] 一句：到这就能用了。可选加一句取舍或延伸（什么场景用别的方案更省事 / 还能怎么扩展）。不升华。
```

省的是原理，不是步骤。一个没碰过的人照着这篇，要能真跑通。
