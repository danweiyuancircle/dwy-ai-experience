适用场景: 在几个技术方案 / 框架 / 库之间做选择，给对比维度和「我选了哪个、为什么」的结论——决策导向，区别于单个工具安利
---

# 方案选型对比模板

定位：帮读者（和未来的自己）做一个技术决策。核心是**对比维度 + 一个明确结论**，敢说「我选 X，不选 Y」。不是把几个方案各夸一遍然后「看需求」。

固定锚点，按顺序：

```
# 标题：点出在选什么、结论（如「Tauri 还是 Electron，我最后选了 Tauri」）

[开篇] 1-2 句：什么场景下要做这个选择 / 我当时纠结什么。

## 候选方案
在比哪几个，各一两句：它是什么、主打什么、为什么进入候选。别长篇介绍，读者只要知道选手是谁。

## 怎么比的
按**真正影响决策**的维度逐条比——包体积、上手成本、生态、性能、踩坑、维护活跃度等，挑这次最关键的几个。每个维度给具体事实 / 数字 / 亲历，别用「优秀 / 良好」这种空泛打分。

## 我的选择
明确结论：选哪个、为什么。再说清什么情况下我会选另一个——让结论可迁移，不绝对化，但也别和稀泥回到「看需求」。

[收尾] 一句：落到「你是 X 场景，直接选 Y」这种能用的建议。
```

选型文章的价值全在那个敢下的结论。把维度摆清楚、把结论说死，读者才省心。
