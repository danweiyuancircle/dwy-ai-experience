# dwy-prototype · 产品原型（低保真 + 高保真）

把产品画成能看能点的原型。两个阶段、两个不同目的：

- **低保真**：灰阶可点线框，验**「是不是用户要的流程和信息架构」**——不验视觉，快是第一目标。
- **高保真**：按端套壳、真实内容、全状态都画出来，①让用户确认视觉和交互细节 ②**作为细 PRD 的底稿**。

## 运行模式

上下文自适应，两种调用方式：

- **单独调用（默认）**：用户直接让你画原型。**先问要哪个阶段**——「低保真验流程，还是高保真做视觉/底稿？」（或两者都要就先低保真再高保真）。从用户描述/已有 PRD 起步；产物落 `./prototype-lowfi/`、`./prototype-hifi/` 或用户指定位置；**不读写 STATE.md、不依赖 `docs/0to1/`**。做完跑对应阶段的「门」即结束。
- **流水线调用**：`dwy-incubator` 调用，指令含「流水线模式」+ `phase=lowfi|hifi` + 前序产物路径 + 落盘路径。按 `phase` 只做指定阶段（编排器会在低保真、高保真各调一次、各卡一道门）；**STATE 记账由 dwy-incubator 负责，本 skill 不碰 STATE.md**。

## 输入（画什么的依据）

- 流水线模式：读编排器给的粗 PRD 拿核心功能；高保真阶段还要看已验过的低保真原型（在它基础上长出来）和目标端。
- 单独模式：有 PRD/低保真就读；没有就先问清要画哪些页面/流程、做哪一端。

## 阶段一：低保真原型

用最快的方式画出可点的灰阶线框，让用户在浏览器点一遍确认走向对不对。这阶段是丢弃式的，**别在好不好看上浪费一分钟**。

### 怎么做

1. 从核心功能拎出**主流程**（用户从进入到完成核心任务走的那条线）。
2. 列出这条线上的页面 + 页面间跳转关系。低保真只覆盖主流程，边角页面先不画。
3. 写**一个 HTML 文件**画出来，规范：
   - **灰阶**：只用黑白灰，方框 + 边框代表区块。
   - **真实文案占位**：按钮、标题写真实文字（「发布」「登录」），别用色块代替文字、别 lorem。
   - **可点跳转**：用锚点 / 简单 JS 切换 div 模拟页面跳转，能点着走完整条流程。
   - **无颜色、无动画、无样式打磨**：不配色、不做圆角阴影、不写过渡动效。
   - **丢弃式**：只为这轮验证，过门后不进开发，别当代码维护。
4. 画完自己在浏览器点一遍，确认整条主流程能走通、没断点，再交给用户。

### 降级（无 GUI 产品 / 单页小工具）

| 产品形态 | 这阶段怎么办 |
|---|---|
| CLI 工具 | 降级为**终端会话 mock**：写一段「用户敲什么命令 → 终端回显什么」的示例对话（纯文本/markdown），验证命令设计和输出格式 |
| 后端 / 库 / SDK | 降级为 **API 契约示例**：列核心接口的请求/响应示例，验证接口形状和调用方式 |
| 完全无 UI（守护进程等） | 跳过原型（流水线模式标 `skipped(无GUI)`） |
| 单页小工具 | 低保真和高保真**合并成一轮**，一次画到位 |

降级产物仍落原型目录（如 `cli-session.md` / `api-contract.md`）。

### 产物 + 门

- 路径：`prototype-lowfi/index.html`（单独默认 `./prototype-lowfi/`；流水线按编排器给的路径）。
- HTML 顶部注释：`<!-- phase: lowfi | status: done | updated: <date +%Y-%m-%d> -->`
- 落盘后**先自己在浏览器验证能点通**再声称完成（先验证再声称）。
- 让用户**在浏览器打开点一遍**（给完整文件路径）。用 `AskUserQuestion`：摆主流程页面清单 + 跳转走向，问「流程对不对、是不是想要的信息架构？通过 / 哪步要改 / 流程重排？」要改就**迭代这个 HTML**再让用户看，直到点头。

## 阶段二：高保真原型

把低保真验过的流程，做成**像成品一样的高保真原型**。它不是「好看一点的低保真」，是细 PRD 的事实依据——**底稿越具体、越覆盖极端情况，细 PRD 越能细到照着写代码**。

### 怎么做

1. 确定端，**按端套壳**：

   | 端 | 套壳 |
   |---|---|
   | iOS | 手机视口（如 390×844）+ iPhone 设备框 |
   | 安卓 | 手机视口 + 安卓设备框 |
   | 桌面 | 窗口框（标题栏 + 内容区） |
   | Web | 响应式，画关键断点（移动 / 桌面至少两套） |

2. 用**真实内容**填充——真实文案、真实数据、真实头像占位图，**不是 lorem**。
3. **每个页面把全状态都画出来**（这是底稿价值所在，别只画「正常态」）：
   - 空状态（列表为空、首次进入）
   - 加载中（骨架屏 / loading）
   - 错误（网络失败、请求出错）
   - 超长文本（标题/正文塞到最长，看怎么折叠/截断）
   - 极端数据（数字很大、列表很多项、零结果）
4. **仍然不做动画**——动效留到开发期，在细 PRD 里用文字描述（如「点赞后图标放大回弹 200ms」）。
5. 用 **HTML** 写（AI 生成 + 浏览器直接看最快），可上颜色、上真实视觉风格。
6. 按页面 / 状态拆多文件，方便逐页对照写细 PRD。

### 产物 + 门

- 路径：`prototype-hifi/`（多文件，如 `home.html`、`home-empty.html`、`publish.html`、`publish-error.html`），建一个 `index.html` 或 `README.md` 做导航。
- 每个 HTML 顶部注释：`<!-- phase: hifi | page: <页面名> | state: <normal/empty/error...> | updated: <date +%Y-%m-%d> -->`
- 落盘后**自己在浏览器逐页看一遍**，确认全状态都画了、套壳对、内容真实，再声称完成。
- 让用户**在浏览器逐页看**（给完整路径和导航）。用 `AskUserQuestion`：摆页面清单 + 每页画了哪些状态 + 套的什么端壳，问「视觉和交互细节确认吗？通过 / 哪页要改 / 哪个状态没覆盖到？」要改就迭代直到确认。

---

## 边界 / 禁止

- **低保真禁止上颜色、做动画、打磨样式、用 lorem 假文、多文件工程化**——只验流程，一个丢弃式 HTML 搞定，快为先。
- **高保真禁止用 lorem 假数据、禁止只画正常态**——真实内容 + 空/加载/错误/超长/极端全状态，才能当细 PRD 底稿。
- **两阶段都不做动画**——动效留到开发期，用文字写进细 PRD。
- **高保真不改流程方向**——流程在低保真已定，要改回低保真重画，别在高保真里偷偷改信息架构。
- **原型不是上线代码**——验证产品形态用；写生产级前端代码是 frontend-design 的事。
