# dwy-prd-coarse · 粗 PRD

和用户一起敲定**功能级**的产品定义：定位、哲学、人群、定价、核心功能详述。这是后面原型和细 PRD 的总纲——纲领定歪了，后面全白做。颗粒度停在功能层面，**不下到页面级**（页面是细 PRD 的事）。

## 运行模式

上下文自适应，两种调用方式：

- **单独调用（默认）**：用户直接让你写/梳理产品 PRD。从用户描述起步；产物落 `./prd-coarse.md` 或用户指定位置；**不读写 STATE.md、不依赖 `docs/0to1/`**。做完跑下方「门」即结束。
- **流水线调用**：`dwy-incubator` 调用，指令含「流水线模式」+ 前序产物路径（市场分析）+ 落盘路径（如 `docs/0to1/04-prd-coarse.md`）。**STATE 记账由 dwy-incubator 负责，本 skill 不碰 STATE.md**。

## 输入（定位/定价的依据）

定位、定价、差异化**不能空想**，要有市场依据：

- 流水线模式：**必须先 Read 编排器给的市场分析产物**，定位看市场空位、定价对标竞品价、功能边界参考竞品。
- 单独模式：有市场分析文档就读；没有就先用一两个问题问清目标人群、已知竞品、大致定价区间，别凭空拍脑袋。

## 怎么做（brainstorming 对话法，逐块敲定）

不要一口气甩一份完整 PRD 让用户看。用对话一块一块谈，谈一块定一块，最后才成稿。对话纪律：

- **一次只问一个问题**，优先选择题（A/B/C 带取舍），比开放题好答。
- 理解清楚后，**提 2-3 个方向带取舍、亮出推荐**那个并说为什么。别替用户默默选，也别什么都「看你」。
- **分段呈现、逐段确认**：每块（定位 / 哲学 / 人群 / 定价 / 功能）谈完先确认这块对不对，再进下一块。
- **YAGNI**：用户列的功能里，砍掉不属于核心的，问清是不是 v1 真需要。

按这个顺序逐块敲定（套 `templates/prd-coarse.md` 的章节）：

1. **产品定位** — 一句话说清「给谁、解决什么、凭什么是你」。从市场空位推。
2. **产品哲学** — 坚持什么、拒绝什么，3-5 条。这是后面所有取舍的判据。
3. **目标人群** — 具体到能想象出一个真人，别写「所有需要 X 的人」。
4. **定价策略** — 档位 + 每档含什么 + 对标竞品。**结合竞品价**，不许凭空标价。
5. **核心功能详述** — 每个功能讲清「是什么、用户拿它干什么、关键规则、边界」。详细到功能层面（输入输出、核心规则、限制），但**不画页面、不定字段长度**。
6. **非目标** — 明确不做什么，挡住后面无穷的「要不要也加个 X」。

每块谈定后，把结论写进产物对应章节（边谈边落，不要等全谈完才动笔）。

## 产物

落盘粗 PRD（单独默认 `./prd-coarse.md`；流水线按编排器给的路径）。套 `templates/prd-coarse.md`。frontmatter：

```
---
status: done        # 成稿前 draft，过门后 done
updated: <date +%Y-%m-%d>
---
```

成稿要件：六个章节齐全；定位/定价能追溯到市场依据；功能详述到功能级；非目标非空。

## 门（过门确认）

分两层确认：

1. **逐块确认**（对话中已做）：每块谈完即时确认，有异议当场改。
2. **整体过门**：六块都谈定、产物已落盘且内容完整后（先验证再声称），用 `AskUserQuestion` 把整份粗 PRD 摆给用户：
   - 摆什么：定位一句话、定价档位、核心功能清单、非目标清单。
   - 问什么：「粗 PRD 这样定，通过 / 哪块要改 / 换方向？」

## 边界 / 禁止

- **禁止脱离市场依据凭空写**：定位/定价要能追溯到竞品和市场空位。
- **禁止下到页面级**：不画页面、不定字段长度/行数（那是 dwy-prd-detailed）。停在功能级。
- **禁止一次甩完整 PRD**：必须 brainstorming 逐块谈、逐块确认。
- **禁止凭空定价**：每个价格档位都要对标竞品。
- 这步**不写任何代码**。
