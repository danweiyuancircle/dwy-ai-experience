# dwy 配置同步

`dwy` 与 `dwy sync` 使用同一交互流程。首次安装运行 `npm install -g create-dwy@latest`，进入项目目录后运行 `dwy`；用户主目录只能选择全局范围。

## 交互顺序

1. 选择当前项目或全局范围。
2. 选择 Skills。
3. 选择 AGENTS.md 通用规范，默认启用。
4. 选择 Hooks，默认启用。
5. 最后选择 CLI。首次只选 Codex；后续恢复当前范围同步过的受支持 CLI 和有效旧托管入口。
6. 按最终 CLI 重新核算全局覆盖，预览实际写入、迁移、备份和清理。
7. 确认后执行，完成页显示实际结果。

不再单独选择内容类型。Skills 用左右键切分类、上下键移动、Space 勾选、`a` 全选或清空当前分类；Enter 确认当前步骤，Esc 或 Ctrl+C 取消。

同步前检查 GitHub `develop` 模板，首次获取可能需要等待。确认前只更新本地模板缓存，不改项目配置、全局配置或已安装共享 Skills；写入目标、迁移、刷新和清理均在确认后执行。

## 全局覆盖与移除

项目检测到有效全局通用规范，或全部所需 Hooks 都有有效全局注册时，完全跳过对应操作页，不重复写入。Hook 是否有效同时检查脚本、事件、matcher 和完整命令注册，不能只看文件存在。

项目 AGENTS.md 由多个 CLI 共享。任一适用 CLI 已有有效的 dwy 全局通用规范时，项目继承全局规范并清理重复基线；最终选择中缺失全局规范的 CLI 会在预览中提示，需要另行选择全局范围补齐，不借项目流程改写全局。手写 AGENTS.md 本身不代表已安装 dwy 全局规范。旧 Rules 托管块与通用规范独立处理，迁移时保留手写内容。

Skills 副本集中在用户目录的 `.dwy/skills`，项目和全局通过目录链接使用。项目选择页将已被全部适用 CLI 的有效全局入口覆盖的 Skills 标注为“全局已启用”并禁选；部分 CLI 已覆盖时仍可选，只为缺少全局入口的 CLI 安装项目链接。主交互先选择 Skills，最后按实际 CLI 重新核算全局覆盖并去重。项目同步不借补入口刷新其他 CLI 正在使用的全局同名共享内容；可刷新共享项的预览明确说明所有同名链接会同时生效。

取消已有 Skills 勾选，或关闭通用规范 / Hooks，只移除当前范围的托管内容。项目操作不移除全局配置，也不改写有效全局提供者。全局启用时会预览当前项目重复项的清理；全局移除不会自动向项目补装。真实目录先备份到同步根的 `.dwy/skill-backups`。

技术栈和开发流程规范改为按需安装的 Skills，不再分发 Rules。项目同步检测到可识别的旧托管 Rules 时，在预览确认后清理对应托管块，不因旧规则自动选择 Skills；由用户自行选择。`.claude/rules` 的旧文件仅在内容与可核实的原模板完全一致时自动清理；不一致或无法核实的文件保留。Cursor 不再提供同步入口，原有 Cursor 配置保留。

推荐按项目选择语言开发、架构、平台或 API Skill，再选择实际使用的基础库 Skill。版本索引只适用于标明的包版本；依赖范围不代表已安装版本，具体接口以项目安装源码及匹配版本为准。

## 远端模板与共享 Skills 更新

默认从公开仓库 `https://github.com/danweiyuancircle/dwy-ai-experience.git` 的 `develop` 分支获取 `dwy-cli/templates/ai-tools`。已获取的 Git 对象和验证后的模板缓存保存在用户目录 `.dwy`，更新时复用；网络失败时优先使用有效缓存，无有效缓存才回退当前 CLI 随包模板，并显示提示。开发时设置 `DWY_TEMPLATE_SOURCE_DIR` 可优先使用本地模板目录。

远端更新需要本机 Git 和可访问 GitHub 的网络；首次获取较慢时会显示进度。成功检查后显示当前模板对应的仓库提交时间（含时区）；无法读取提交时间时显示未知。无法获取最新版本时，提示中的缓存或随包版本可能落后，不应当成已同步到最新。

Skills 新增或变更推送到 `develop` 后，无需为内容变更单独发布 CLI；下次运行同步或 `dwy refresh` 会检查最新模板。CLI 程序自身改变仍需通过 CLI 更新交付。

| 入口 | 用途 |
| --- | --- |
| `dwy` / `dwy sync` | 获取最新模板，确认后同步所选配置，并刷新本次所选、需由当前范围提供的共享 Skills |
| `dwy refresh` | 获取最新模板并刷新已安装共享 Skills；已有链接同时生效 |
| `dwy upgrade` | 更新到 npm 最新正式版程序，并刷新共享 Skills |
| `dwy migrate` | 迁移当前项目已有托管 Skills，真实目录先备份，无需重新勾选 |

`dwy upgrade` 默认从 npm 官方源查询并安装同一精确版本，避免本机镜像的 `latest` 滞后；显式设置 `npm_config_registry` 时查询与安装都使用该源，不修改用户的 registry 配置。安装后回读当前 PATH 中的 `dwy --version`，版本一致才刷新并报告成功；刷新失败单独报错。

Hooks 更新仍需执行 `dwy sync`。已有会话可能缓存 Skill 内容，需要重新加载。个人 Skills、Rules、Hooks 不参与 `dwy migrate`；脚本层的 sync / migrate 接口仍须显式指定范围，不从上一次交互猜测。
