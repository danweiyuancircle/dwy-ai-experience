# chances-apk-项目方案 Skill 草案

本草案约定 Skill 的行为和固定输出，尚未安装 Skill，也未创建飞书方案副本。

## 定位与工具

- 展示名称：`chances-apk-项目方案`；Skill 标识：`chances-apk-project-plan`。
- 触发场景：按需求编写 APK 研发方案、按飞书模板新建项目方案、补充已有方案。
- 只要求讨论或草案时不写飞书；要求新建方案时，复制模板后完成填写与回读。明确更新已有文档时原地更新指定范围。
- 复用已安装的 `lark-doc`、`lark-drive`、`lark-sheets` 与 `lark-cli`，按具体操作读取其说明，不另写飞书 API 封装。需求来自 Jira 时使用现有 `jira-integration`；测试用例需要新建时复用 `chances-feishu-testcases`。
- 工具来源：[飞书官方 CLI](https://github.com/larksuite/cli)。本轮已验证本机 `1.0.97` 可读取模板及研发计划表；不安装或升级工具，不调整账号及文档权限。业务资料仅通过已授权的飞书/Jira 工具处理，不另传第三方服务。
- 本仓库及 npm 包公开。此 Skill 含团队模板入口，建议与现有 Chances 测试用例 Skill 一起存放在团队技能库，不默认打入公共 CLI 包；本草案不进行发布、提交或推送。

## 模板与标题

默认模板：[APK 研发方案模板](https://chances.feishu.cn/docx/VMeQd3AanoEPpLxv1RRcFoGKnGc)。本轮读取修订号为 `451`；执行 Skill 时重新读取最新模板，不把本草案快照当成永久格式。

文档名称沿用模板：`项目名-版本号-阶段子版本号-Apk研发方案`。阶段子版本没有定义时省略这一段，不造一个编号。若项目已有完整版本标识，则保留原标识，不重复拼接。

项目与版本依据按以下顺序确定：

1. 用户本轮明确指定的项目、目标版本、APK 或发布任务。
2. 本轮需求、同版方案及明确关联的发布记录。
3. 目标应用、目标 flavor 与构建变体实际生效的构建配置，包括 Gradle、版本配置文件或 CI 覆盖值。

区分目标版本与当前源码版本；`versionName`、`versionCode`、阶段子版本不能未经依据互相替代。模板标题、工具仓库版本与历史记录不作为本次目标版本。关键版本有冲突时先完成内容草稿，只询问无法核实的冲突项，不带猜测发布成正式方案。

## 上下文读取

先整理本轮需求范围，再按范围读取相关资料：用户说明与附件、需求链接及验收条件、目标仓库规则与构建配置、相关提交和调用链、涉及的接口与配置说明。

只读取授权且相关的项目；不因模板出现链接就扩大到其他业务。模板只提供结构，不能把其示例或其他项目业务当作当前事实。

写作时区分三类信息：代码或资料已证实的现状、本次拟实施的设计、尚待确认的信息。关键结论附可定位的需求链接或仓库相对路径，集中在相关段落，不逐句堆引用。计划中的文件与接口标注“拟新增”，不能写成已经存在。

## 固定正文

保留模板的五个一级章节及顺序；“实现方案”按本次需求重复功能小节。以下为填充口径，不将说明文字原样放入交付文档。

### 一、需求文档

列出需求编号、简短名称、完整链接及本次范围。没有 Jira 编号时使用需求简称，不造编号；只有用户口述时注明“来源：本次需求说明”，不造链接。

### 二、实现方案

每项需求使用二级标题 `Jira需求编号-功能简述`；没有编号时使用功能简述。每项依次填写：

| 字段 | 填写规则 |
| --- | --- |
| 开发者 | 有明确负责人时填写；仅姓名时写姓名，真实成员身份可解析时才使用飞书提及。缺失写“待分配”，不默认文档作者。 |
| 实现说明 | 依次说明当前行为或问题、用户在哪种操作下触发、修改后的处理过程、用户最终看到什么；涉及异常、异步或兼容时补充其处理。先写人能理解的行为，再解释必要的代码落点。 |
| 流程图 | 分支、异步回调或跨模块流程较复杂时画主要变化；简单改动写“无（处理过程见实现说明）”。使用飞书可读的原生图或插图，不把未渲染的 Mermaid 代码当成已交付流程图。 |
| 涉及功能 | 列出实际受影响的功能，如直播、收藏、鉴权、播放器；不把整个 APK 都列入。 |
| 涉及文件 | 分“新增”“修改”列出仓库根开始的相对路径，并用一句话说明用途；没有则写“无”。设计阶段未存在的路径标“拟新增”。 |
| 参数配置 | 分“网站参数”“其他配置”。网站参数用表格写清参数名、JSON 类型、默认值、含义和生效条件；未定义默认值写“无默认值”或“待确认”，不能自造。只记录本次相关配置，无变化写“无”。 |
| linkType | 新增或修改 Activity 跳转时填写真实或拟定的跳转值、参数、入口和前置条件；不涉及写“无”。拟定值需标注，不造已存在的跳转协议。 |
| 涉及接口和数据结构 | 写清新增或变更的请求方式、完整 URL、关键请求/响应字段、类型、兼容要求。环境主机未知时写明来源配置项及已知接口路径，不猜完整地址；没有变化写“无”。只列变更相关字段，不粘贴整份响应。 |

“无”表示确认不涉及；“待确认”表示会影响方案但证据不足，二者不能混用。

可读性示例（仅示意，不代表本次业务）：

> 当前快速连续切台时，上一个频道的鉴权结果可能覆盖新频道。本次为每次切台记录当前请求；鉴权返回后先核对请求是否仍对应当前频道，过期结果不再触发播放。用户连续切台后应播放最后一次选择的频道，过期失败结果也不应弹出错误提示。

避免只写“优化逻辑、增强健壮性、提升体验”，也不以方法名清单代替处理过程。

### 三、研发计划

沿用模板内嵌电子表格的六列与四行，不另外造排期体系。

| 项目 | 预估时间（人日） | 实际时间（人日） | 计划开始时间 | 实际开始时间 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 方案编写 | 依据范围估算 | 有实际记录才填 | 有排期才填 | 有实际记录才填 | 估算依据或依赖 |
| 测试用例编写 | 依据范围估算 | 有实际记录才填 | 有排期才填 | 有实际记录才填 | 估算依据或依赖 |
| 开发时间 | 依据范围估算 | 有实际记录才填 | 有排期才填 | 有实际记录才填 | 估算依据或依赖 |
| 自测时间 | 依据范围估算 | 有实际记录才填 | 有排期才填 | 有实际记录才填 | 设备与联调依赖 |

无法估算时留空并在备注说明缺少的条件；估算标注为预估，不作为已承诺排期。未知实际数据留空。

### 四、升级计划

说明是否需要后台、配置、数据或 APK 更新，存在依赖时明确顺序、旧版本兼容及失败后的恢复方式。核实只需 APK 更新时写“无需后台更新，前端更新即可”，再列实际升级注意事项。上线时间未定不造日期；未确认后台依赖时写待确认，不能直接判定无需后台更新。

### 五、测试用例

优先引用本次项目及版本已有的测试用例文档。用户要求一并生成，或明确要求交付包含测试用例的完整方案时，复用 `chances-feishu-testcases` 新建并回填链接；只要求方案时不额外创建测试表，无同版用例则写“待补充”，列出需要覆盖的核心场景。

测试内容要能由人复测：正常路径、实际涉及的异常与兼容场景，以及明确的预期结果。不要把拟执行用例写成已通过，也不能用单元测试结论冒充机顶盒验收。

## 飞书执行流程

1. 读取最新模板，确认标题层级、正文、样式及内嵌资源；先完成上下文核对与方案内容草稿。
2. 新建时使用 `lark-cli drive +copy` 复制整篇模板；指定新名称和目标文件夹。未指定目录时复制到当前用户“我的空间”，交付时说明位置，不改原模板。具体参数以当前安装版本的 Skill 和 `--help` 为准。
3. 保存返回的新文档标识和 URL，确认它不同于模板；之后仅编辑该副本。核对副本的内嵌表格是否为独立资源。若仍引用模板源表，不向源表写入；先通过已支持能力创建独立副本并重新关联。无法安全处理时保留草稿并报告阻塞，不默默改成另一种表格。
4. 按 `lark-doc` 更新说明逐节填入，保留标题与样式；清理模板的填写提示、`xxx`、开发者占位等。新增内容按副本的真实结构定位，不沿用原模板的块 ID。
5. 写入失败后从已保存的副本继续；复制超时且结果不明时先核对是否已创建，不盲目重复复制。部分完成时返回已有副本链接、完成范围和剩余事项。
6. 回读文档及研发计划表：核对标题、全部章节、每项需求、配置表、链接、流程图和嵌入资源；没有占位说明、其他项目内容、凭据或本机绝对路径。未通过回读不能宣称方案已完成。

普通复制和新副本填写在用户要求新建方案时直接执行；删除、公开分享、修改模板和覆盖无关文档不在默认范围。

## 固定交付格式

执行 Skill 后的聊天交付统一为以下字段，正文留在飞书：

```text
方案：文档标题（附完整飞书文档链接）
项目 / 版本：已核实的项目与目标版本
覆盖需求：需求编号或简短名称
测试用例：同版用例链接；未创建时说明状态
待确认：影响实施或验收的事项；没有则写“无”
校验：实际完成的回读检查，以及尚未验证的内容
```

只交付草案、部分写入或遇到阻塞时明确写出状态，不套用完成口径。

## 验证边界

正式启用 Skill 前验证：多需求能逐项填充；简单改动不强画图；未知版本不猜；缺失实际工时留空；重复执行能续写已有副本；复制后研发计划资源独立；测试用例链接对应同版；写后读回没有模板提示。

本轮仅验证模板和源研发计划表可读取。尚未验证真实复制、内嵌表格复制语义、图形渲染和写后回读，需要在首次实际创建方案时完成，不提前承诺。
