# 通知展示归属

已确认：dwy-notify 只提供基础展示参数；每个目标最终必须有发送者名称，由应用、URL 显式设置或具体模块预设提供，缺少时在任何网络请求前拒绝。名称不能设为 null，正文标题不代替发送者名称。公网 HTTPS 头像可选，未设置或显式 null 时使用平台默认头像。业务名称与 Logo 由 dwy-webhooks 的购买、审核、经营和邮件模块预设，其余使用系统通知。应用可按字段覆盖。

复用已安装 Apprise 和公开 GitHub 仓库，不新增运行时依赖或图片服务。PNG 与原始 SVG、来源许可一并提交，默认 URL 固定到仅含资产的提交 SHA。GitHub 托管仅上传公开图标；不发布 Python 包、不部署 App Cloud、不发送真实通知。

覆盖顺序：单次调用 > 应用 NotificationConfig > 目标 URL 显式设置 > Webhook 模块预设。展示参数不影响目标指纹和接收方去重。预设随现有 JSON outbox 首次发送持久化，重试保留；无数据库迁移。

方案比较：GitHub 固定资产提交不增加运维；独立对象存储需要额外配置和维护；只打进 wheel 无法供 Discord 公网读取。采用第一种，应用可以覆盖为自己的公开地址。

验收：默认请求不含头像；预设、自定义、显式清除、并发与重试正确；GitHub 匿名图片可访问；现有消息正文、投递预算和来源隔离不变。
