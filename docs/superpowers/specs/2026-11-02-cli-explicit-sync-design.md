# CLI 显式作用范围与同步内容

用户已确认执行以下流程，不再增加设计确认步骤。

## 流程和边界

1. 选择当前项目或全局。
2. 选择该范围支持的平台；全局不提供 Cursor。
3. 选择本次处理的类型，默认只选择 Skills。项目提供 Skills、项目 Rules、Hooks；全局提供 Skills、全局通用规范、Hooks。按平台能力过滤类型。
4. 逐项选择已启用的类型：Skills 和项目 Rules 保留分类 Tab；Hooks 在选择这一类型后按平台自动同步；全局通用规范展示摘要。
5. 先计算只读变更清单，预览后确认；执行同一份清单。未选择的类型不写入、不清理，也不清空同步记录。

## Skills 语义

- 默认勾选仅来自所选范围和平台，不混入另一范围或未选平台。
- 项目选择：所有所选适用平台均有有效全局入口时显示“全局已启用”并禁止重复勾选；部分平台有全局入口时仍可选，只给缺少全局入口的平台建立项目链接。
- 取消已有勾选表示移除当前范围的托管入口，选择页明确说明；个人条目保留，原真实目录先备份。
- 项目同步不迁移或改写全局入口。全局优先去重只备份并清理当前项目重复入口，清单中单独列出。
- sync / migrate 为缺失项准备共享副本，不更新已经存在的共享内容。refresh / upgrade 继续负责更新共享内容。

## 其他内容

- 项目 Rules 只写项目根托管块和 Cursor 原生规则；未选 Rules 时保留既有内容。
- 全局通用规范只有显式选择才更新各工具原生全局指令入口，不改项目 Rules。
- Hooks 只有显式选择此类型才处理，按平台支持范围自动同步，保留个人配置。
- 旧同步状态继续可读；只有实际处理的类型和入口更新记录，项目共享的 Rules 记录保持一致。

## 实现与验证

- 复用现有终端选择器、平台适配、目录链接和备份能力，不增加依赖。
- 将变更清单独立于交互计算，确认前不得写缓存、配置或备份。
- 测试覆盖真实终端步骤顺序、取消、禁用条目的 Space / 全选、全部与部分全局覆盖、范围隔离、未选类型保留、共享内容不刷新、预览与执行一致和旧状态迁移。
- 实施与验证阶段不自动发布；提交发布按后续用户授权执行，不触碰其他并行开发内容。
