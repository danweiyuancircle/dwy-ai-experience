# CLI 配置启停与全局继承

用户已确认本方案并要求实施。

## 交互与内容

- 线性流程：范围 → 平台 → 本次管理内容 → 启用/移除 → 清单确认。
- 全局提供 Skills、Hooks、AGENTS.md 通用规范；项目另外提供 Rules。按平台现有能力过滤，Cursor 仍仅项目 Rules。
- 全局首次默认选择 Skills 和通用规范；显式移除过通用规范的平台不再因默认值重新启用。项目默认只选 Skills。
- Skills 保留逐项勾选；Hooks 继续按平台管理整组，增加显式移除整组的动作，不引入 Skill 依赖。通用规范提供启用/更新、移除。
- 未选择类型保持原样；移除必须显式选择并出现在确认清单。取消不写文件。

## 继承与去重

- Skills 沿用有效全局入口、禁用重复勾选、部分平台只补缺失入口。
- Hooks 的全局有效性要求脚本存在且在对应事件、matcher 下注册了实际执行命令，不能仅凭文件或历史状态判断。项目只安装缺少全局提供者的 Hook；全局已提供的项目重复脚本和注册项在清单中明确清理。
- 全局启用 Hooks 后也清理当前项目重复项，不扫描其他项目。全局移除不自动往项目补装。
- 通用规范按 dwy 基线托管块识别，手写 AGENTS.md 本身不代表已全局安装。多平台共用项目根 AGENTS.md，任一所选 CLI 已有有效全局基线时，项目禁止安装基线，只允许显式清理项目重复块；缺失的平台提示补全其全局规范。
- 全局启用基线时清理当前项目的重复基线块；全局移除不自动回填项目。已知旧基线入口纳入显式清理，无法识别归属的手写内容保留。

## 文件与状态

- 项目 AGENTS.md 的通用基线块、Rules 块和个人内容独立更新，任何一项移除都不能删除另一项。全局同样保留其他托管块及手写内容。
- Claude 全局沿用原生 CLAUDE.md，Codex 遵循 CODEX_HOME，OpenCode 沿用原生 AGENTS.md；界面同时显示逻辑名称及实际路径。
- 新增平台状态 baseline 布尔值表示显式启停；旧状态继续可读，实际配置用于判断继承。项目共享文件的基线记录保持一致。
- 清理 Hook 时只处理模板/已知历史托管名称及匹配命令，保留个人脚本、个人命令和非 Hooks 配置。配置路径链接不能导致改写全局提供者或外部目标。
- sync / migrate 不刷新已有共享 Skills，refresh / upgrade 继续负责刷新。保持既有 Skills 备份与根链接保护。

## 方案选择与验证

采用已有同步计划与平台适配器，增加有效继承检查、明确动作和独立基线写入。未采用未勾选即删除整类的方式，避免已有流程误删；未采用跨项目自动回填，避免隐藏写入。

测试覆盖：全局首次默认及移除记忆、项目基线与 Rules 独立、手写文件不误判、混合平台基线禁装、Hook 注册缺失/脚本缺失/部分覆盖/重复清理/移除、个人内容与自定义 Codex 目录保留、软链接边界、只读清单和真实终端取消。

实施阶段直接在 develop 工作目录开发，不新增依赖、不改其他未提交内容。提交、发布和本机全局更新按后续用户授权执行。
