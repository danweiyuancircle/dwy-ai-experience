# CLI 共享 Skills 副本与软链接

## 目标与已确定的行为

- CLI 维护用户级共享副本，项目不再各自复制 Skills；刷新一次，所有已迁移的入口读取新内容。
- 同平台全局入口优先：发现有效的同名全局 Skill 时，当前项目不创建重复入口，并清理该项目内 CLI 管理的重复副本。
- 不更改 Rules、Hooks、通用基线的存放方式，不扫描或改写其他项目。

## 方案取舍

- 继续逐项目复制：需要逐个项目更新，不满足目标。
- 直接链接 npm 包安装目录：全局升级或切换包管理器后目录可能变化，不采用。
- 稳定用户目录保存副本，按 Skill 建链接：采用用户提出的共享副本与软链接方案；具体目录由实现选用现有用户根下的 `.dwy/skills/<name>`，不包含版本号或分类名。

## 副本与入口

- 内容继续来自当前 CLI 包内的 `templates/ai-tools/skills`，不新增外部拉取源或运行时依赖。
- 项目入口和全局入口都链接整个 Skill 目录，涵盖 `SKILL.md`、引用文件、脚本等；父目录保持真实目录。
- 项目同步先检查对应平台可发现的全局入口；只有有效的 `SKILL.md` 才视为已全局安装。损坏链接不能作为删除项目副本的依据。
- 同轮兼容脚本同时选择项目和全局时，先成功建立全局入口，再决定项目入口，不能只检查同步开始前的磁盘状态。
- OpenCode 同时发现自身目录、Claude 和 `.agents` 的兼容目录，去重判断遵循实际发现范围。Codex 支持目录软链接，扫描本地安装项时须跟随目录链接，同时识别坏链以便修复或清理。
- 保留现有平台选择范围，只清理 CLI 管理的同名条目；用户自定义 Skill 不纳入同步删除。

## 刷新与升级

- 新增公开命令 `dwy refresh`：使用当前安装包模板刷新共享目录中已安装的 Skills，不进入项目选择，不重写项目入口。
- 新增公开命令 `dwy migrate`：在老项目根目录一键迁移已有的 CLI Skills，无需重新勾选；按模板名称和历史同步记录识别托管条目，未知历史条目保留并报告，规则和 Hooks 不变。重复执行不产生重复备份。
- `dwy` / `dwy sync` 写入口前先准备所需的共享副本；既有链接随副本更新生效。
- `dwy upgrade` 安装新 CLI 成功后，调用新安装的 `dwy refresh`，避免 pnpm 等升级后仍读取旧进程加载的包路径；已经是最新版本时也刷新共享副本。
- 外部直接升级包后执行一次 `dwy refresh` 即可，无需进入各项目同步。
- 新包已经移除的 Skill 暂保留旧副本并报告，不自动删共享目录而使其他项目链接失效；本轮不增加全局垃圾回收。
- 刷新先准备完整新副本再替换，失败保留旧内容并报错；不把部分更新或刷新失败报告为成功。

## 迁移与边界

- 旧项目的真实副本仍需首次在该项目执行同步，之后转为链接；CLI 无法凭共享目录定位所有历史项目。
- 替换已有真实目录或因全局优先清理项目真实副本时，先备份到该同步根的 `.dwy/skill-backups`，避免丢失用户在目录里添加或修改的文件；需要保留入口时再建立链接。删除已有软链接只操作入口，不删除其目标。
- 同步预览说明将迁移或删除的项目入口；最后取消时不写共享副本、不迁移、不删除。
- 同步状态分别记录项目实际保留的入口和全局入口，不能把由全局提供的 Skill 再记为项目安装。
- 默认勾选仍合并有效全局选择；仅 Skills 模式更新项目状态时保留全局记录，避免去重后下次丢失选择。
- 链接只保证当前机器的路径有效；跨机器克隆或迁移后需重新同步。现有会话可能缓存 Skill，刷新不承诺让运行中的会话重新加载。
- macOS / Linux 使用目录软链接，Windows 使用目录 junction；Windows 行为遵循 Node.js API，未在真实 Windows 环境验收前不宣称跨平台实测通过。

## 涉及范围与验证

- 共享目录管理、总同步编排及 Claude / Codex / OpenCode 的 Skill 写入和扫描。
- 兼容现有全局位置脚本接口和仅 Skills 模式；更新升级入口、CLI 帮助及相关使用说明。
- 测试覆盖：两个项目共享同一目标、刷新后同时读取新内容、已有目录迁移及备份、坏链修复、全局优先和跨平台发现范围、取消无写入、删除入口不删共享内容、自定义 Skill 保留、复制或刷新失败不丢旧数据、升级后的刷新调用。
- 运行 CLI 全量测试和补丁格式检查；保留本轮已有的 `dwy-publish` CHANGELOG 规则改动，不顺带提交、打标签或发布。
