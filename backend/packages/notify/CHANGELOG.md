# dwy-notify

## 0.3.3 - 2026-11-09

- 事件增加可选默认展示；relay 和 SQLAlchemy 队列贯通逐事件名称与头像，入队保存快照并在重试时复用，保留显式应用配置的覆盖优先级。

## 0.3.2

发布日期：2026-11-05。

- 将 `dwyeapi` 的精确版本约束改为 `>=0.12.1,<0.13`，允许兼容补丁升级；通知发送、持久队列和资金事件内容均不变。

## 0.3.1

- 新增来源无关的 NotificationField 和有 UTF-8 字节预算的 render_notification_fields，外部项目可显式传入有序展示字段；保留标签、标记截断，不改变发送和持久队列接口。

## 0.3.0

- 新增 `SQLAlchemyDeliveryQueue.enqueue_in_session`，可与宿主业务状态共用事务；重复事件不会中断外层事务，原有 `enqueue` 继续自行提交。
- 新增 `requeue_failed_in_session`，仅重放显式指定的失败目标；原子锁定记录并拒绝活跃租约、成功目标、新接收方及目标指纹变更，保留原正文与展示快照。
- 队列入参校验 scope 与事件标识长度、非空白正文及 65536 字符正文上限；无效输入返回固定安全原因，不截断内容。
- 消费者按已有 `allowed_scopes` 参数在领取 SQL 中筛选；同表其它 scope 的积压状态、正文及租约保持原样，空集合不领取记录。

## 0.2.1

- 提供来源无关的事件合同、通知 relay、目标配置适配和逐目标可靠投递函数；展示预设由调用模块显式注入。
- 提供可选 SQLAlchemy 持久队列适配，沿用表字段、租约、目标指纹与历史消息 payload，支持部分成功恢复。
- 保留历史 Discord 配置的 URL 指纹与显式名称优先级；基础层不导入 Apple、邮件或旧 Webhook 业务包。

## 0.2.0

- 发送者名称必须由调用方配置、URL 显式设置或业务模块预设提供；合并后缺少名称时，在任何目标发出请求前拒绝。旧的无名称调用需要补充名称。
- 新增基础展示模型，支持逐字段覆盖；头像可省略或显式清除，默认使用平台头像，不再自动使用 Apprise Logo。
- 单次设置、应用配置、URL 显式设置与业务默认依次覆盖；保留 legacy 隐式名称的低优先级与既有目标指纹，支持并发隔离。

## 0.1.0

- 首次发布独立多目标异步通知、安全 HTTP 边界和逐目标结果契约。
