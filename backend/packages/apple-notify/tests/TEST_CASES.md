# dwy-apple-notify 测试覆盖

- `analytics/test_monitor.py`：按应用关闭日报后，周一只有周报、次日静默采集，真实 SQLite 保存八日快照且重启不会重复发送；默认日报加周报保持原行为。

- `test_apple_appearance.py`：订阅购买、买断购买、已退款、通用动态四类；只将明确生产本人非零交易判为购买，关闭续订携带原价格仍为动态；共享／免费／缺字段／未知商品／已撤销／Sandbox 均不冒充付费；申请、驳回、撤销退款与真实退款分开；SDK 商品类型、router 展示与八字段公共数据合同、SVG／PNG 和许可随 wheel 打包。

- 包边界：独立配置只包含 Apple 来源，不导入旧 dwy-webhooks 或邮件适配；无外部 lag_days 参数。
- 购买：官方 SDK 方法边界、身份匹配、嵌套交易验签、并发关闭、取消与安全错误；购买/退款/续订文案及金额零值。
- App 首次获取平台：按交易编号查询并验签 App 交易，已知平台显示、缺失和未知平台安全降级；旧通知不添加字段。
- 家庭共享：首次获权、重新获权和续期与本人购买区分；价格标明无新增付款，保留到期、退款、撤销及关闭续订语义，缺失或未知归属不当作共享。
- ASC：HMAC 原始载荷验签、事件筛选、版本查询与错误响应，凭据不进入公共事件。
- 评论：分页、游标、基线、地区与评分文案、保留期、去重、历史范围与租约；独立宿主生命周期。
- Analytics：报表发现、分页与分片、下载边界、gzip/TSV、金额与订阅指标、缺失状态、日报周报。
- 真实订阅结构：Event Group/Event Name 与文档列名统一、歧义重名拒绝、Paid subscription start 计数；无 State Metric Grouping 时按实际状态计算存量，未知状态保持不可用。
- 采集失败原因：日志保留解析失败/超时安全错误码，不含异常正文与签名下载地址；失败不写部分快照或完成状态。
- 采集瞬断：GET 网络异常最多尝试三次、间隔 1/2 秒；中途断流丢弃半截正文；持续失败保留安全错误，POST、HTTP 状态和无效载荷不重试，取消立即传播。
- 运行时诊断：请求关联号、操作、尝试序号、连接/TLS/收头/收体阶段、HTTP 状态、异常类名和耗时；整轮关联号、失败日期和总耗时。trace 参数、URL、请求头、异常正文和响应内容不进入日志。
- 报表展示：日报、周报固定列出全部指标和地区/来源 Top 3；缺失、待发布、不适用、空值及非 USD 金额显示“无数据”，真实零值保留，缺日周汇总不补零，内部状态不变。
- 统计日期：08:30 发送边界、30 日取 28 日、31 日取 29 日、跨月跨年、周一周报与历史比较；拒绝 lag_days。
- 存储与投递：固定表结构、来源与范围隔离、账号/App 租约、原子快照/outbox、失败与重启恢复。
- 实际 wheel：iap、asc、analytics 的隔离导入与离线链路，不依赖 App Cloud 或 Resend；仅真实发布产物可作为验收证据。

## 评分日报

`tests/ratings/test_models_client.py` 与 `tests/ratings/test_daily.py` 使用 MockTransport、注入时钟和真实文件 SQLite；不向 Apple 或通知平台发送请求。

- 配置：独立应用名单、双字母地区去重、IANA 时区、小时/分钟边界、至少 32 天保留期、默认北京时间 08:30。
- Lookup：固定公开 HTTPS 目标、精确 App ID 和已配置地区、只读全版本字段；原始均分精度与真实零评分保留。
- 外部校验：错误 App ID、空结果、缺失字段、布尔/浮点评分数、负数、BigInteger 溢出、无效均分、零值矛盾、限流、重定向、超时、无效 JSON、递归过深 JSON 和超大响应拒绝；HTTP 不重试，错误不泄露正文，注入客户端不被关闭。
- 日期与展示：昨天/七天前/上月同日、月底闰年及跨年；累计评分下降、精确均分差、小于展示精度变化；缺历史与基准日失败区分，旧历史存在时不误报首次采集。
- 每日调度：发送时间前跳过、首次采集、同日重复与重启去重、并发 worker 只采集一次、全部地区共用一份汇总；停机跨日不补造历史，跨午夜不将今日值记成昨天。
- 午夜迟交：连续两天 23:59:50 首请求耗时跨日时，各生成一份全失败日报；停止后续地区网络，计划日 completed 不重拉，次日到点前不发起新查询。跨日整轮丢弃部分成功值，失败快照保存计划日及实际完成时间，日报明确提示跨日；未来日、跨日成功值及过期租约的直接写入仍拒绝。
- 失败与恢复：部分地区失败定稿日报且同日不重采集，旧成功快照不被零或旧值覆盖；投递失败仅重试固定内容；意外内部异常传播，不伪装为业务失败日报。
- 深层 JSON：真实 Lookup 客户端将 2000 层、4001 字节嵌套响应转成 `rating_invalid_response`，日报保留失败项并继续其它应用，同日重复调度不再请求 Apple。
- 持久原子性：过期/被替换租约不能写历史和 outbox，旧 worker 不能释放新租约；取消可恢复；模拟 outbox 插入失败回滚 state 和 snapshots，随后可恢复。
- 历史与隔离：清理过期快照，保留月度基准；应用、地区、时区与表前缀隔离，切换时区保留待发定稿日报。
- 名单撤销：每个日报分段保存全部应用 ID；部分应用撤销、完整停用后以子集重新启用时，旧汇总整份 suppressed 并清空 payload，不重算、不采集；时区变化且名单未撤销仍可发送。
- 生命周期与长文：重复安装/无通知目标拒绝；显式 `runtime.monitor/queue` 和 FastAPI state；仅关闭库创建的客户端；长应用名单与非 BMP 字符无损分段且每段不超过 2000 UTF-16 单位，零评分正常汇报。

本轮实际 wheel、宿主迁移与目标环境验收由集成报告单独记录，源码测试不能代替这些检查。

`tests/ratings_wheel_smoke.py` 为发布工作流的独立 wheel 验收脚本：仅安装实际 wheel 的 `ratings` extra 与固定 SQLite 测试驱动，在仓库外运行；检查传入发行版本和虚拟环境导入来源，确认 App Cloud、旧业务包、IAP 与邮件适配不在环境中。配置北京时间 09:30，用 MockTransport 读取全版本评分，真实 SQLite 验证定时边界、持久快照、日周月变化、原始均分精度、真实零评分和整份 outbox；首次发送失败后只重试固定正文，不重新采集；最后关闭 HTTP 与数据库引擎。发布前先确认不含 ratings 的旧 wheel 导入失败，再验证本轮实际 wheel；源码路径和宿主环境不可代替此项。
