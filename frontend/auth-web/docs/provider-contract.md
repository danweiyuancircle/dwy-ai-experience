# Web 认证 Provider 合同设计

状态：共享管理组件首批设计交付。本文不是已发布 API；本批不新增普通用户运行时导出，不替换现有 AdminLogin / createAdminAuthApi / createAdminSession。

## 目标与边界

下一批从 quant 抽取普通用户认证 UI，通过宿主 Provider 对接现有后端。保留管理员独立 Cookie 和普通用户 JWT 两种身份体系。通用包不导入产品 store、全局 HTTP、后端模型、套餐、配额或环境变量。

认证成功不等于授权所有业务操作。前端 admin/user 只用于显示与导航；后端继续校验角色或独立管理员会话，以及本人的业务数据作用域。

## 必需会话能力

建议将以下三类职责分开，下一批实现前对最终 TypeScript 签名做消费者编译验证：

| 端口 | 输入/输出 | 责任 |
|---|---|---|
| SessionProvider.restore | 无凭据输入，返回安全身份或未登录 | 由服务端确认，不从 localStorage role 推导权限 |
| PasswordSignIn.signIn | identifier/password 和可选人工验证凭据，返回安全身份 | identifier 是邮箱或用户名由宿主表单策略指定；不把昵称当登录名 |
| SessionProvider.signOut | 返回撤销成功或失败 | 只有服务端成功撤销后清身份；失败保留重试能力 |

安全身份只包含稳定展示键、显示名及服务端确认的 admin/user；管理员 Cookie 适配器可使用其已验证用户名作展示键，普通用户适配器使用服务端主体 UUID。该键不能作为后端认证材料。

会话刷新、access/refresh 的存放及 Cookie 属性由 Provider/transport 管理，UI 不读写凭据。现有管理员 API 继续同源；本机前端连接远端通过宿主反向代理。禁止把支持跨域当成简单的 withCredentials 开关。

## 可选能力按合同分组

| 能力组 | 供给方式 | 不可默认假定 |
|---|---|---|
| 邮箱码注册 | 请求验证码、提交挑战/验证码/新密码等由 Provider 提供 | 所有后端使用相同 challenge ID 或都带人工验证 |
| 新密码策略 | requirements + validateNewPassword；错误可定位字段 | 登录旧密码也满足当前新设密规则 |
| 密码重置 | 使用明确的重置模式，见下节 | 统一换一下 URL 就能适配 |
| 人工验证 | 宿主 ChallengeProvider，提供取消、过期和验证结果 | 前端 PoW 成功可代替后端一次性验证 |
| 安全设置 | 改密/首次设密、邮箱修改等按后端能力启用 | shared AuthRuntime 已实现 quant 的全部邮箱设置接口 |
| 外部登录 | 宿主提供获取凭据/跳转动作与结果处理 | 存在后端 ID-token verifier 就已经完成 Google Web OAuth |

UI 从实际 Provider 能力确定入口与字段，不渲染“存在但提交永远失败”的假功能。拒绝把几十个 optional 方法放进一个万能对象；模式和功能组用明确类型区分。

## 密码重置的两个合同

1. `verified-token`：quant 请求邮件码，verifyCode 成功后得到短期 reset context，再提交新密码。reset token 只留当前流程内存，不进入路由、日志、持久化或协议偏好。
2. `challenge-submit`：shared 请求 challenge，提交 challenge ID、验证码和新密码，由服务端在同一次操作校验并消费。UI 不提前宣称验证码已通过服务端验证。

两个模式共享字段、倒计时、错误和布局；各自保持真实服务端步骤，不使用总是成功的 verify 适配器伪装统一合同。

quant 新密码至少 8 码点、三类字符、最多 72 UTF-8 字节；shared 邮箱认证至少 15 码点、最多 72 字节。保留 Provider 校验与服务端规则的一致性，本批不改变任何一套策略。

## 宿主必须注入

- API 地址、HTTP 信封/错误码归一化和会话 transport；日志不能回显密码、验证码、token 或完整敏感响应。
- 品牌、公司文案、协议与隐私正文/链接/版本；不能把 quant 的金融服务协议作为公共默认。
- 路由与认证成功回调：是否新开标签、控制台/营销页面跳转属于宿主策略。
- 人工验证与可选外部登录；安全字段只短期传输，不进入通用表单持久化。
- 错误映射：无效凭据、已存在、验证码错误/过期、限流及冷却时间、服务不可用、网络错误、字段错误；页面不展示原始数据库或 HTTP 堆栈。

不可信 redirect 仍必须校验为站内路由。导航失败与登录失败分别处理；认证已成功时提供重试导航入口，不再次偷偷登录。

## 多标签页与异步安全

Provider 的登录、刷新、退出握手应共用按后端会话空间隔离的协调键；Web Locks 优先，无该 API 时注明本标签队列的保证边界。使用非敏感代次淘汰旧账户响应，阻止迟到 Cookie 握手覆盖新登录。

跨标签只通知身份失效/换号和非敏感代次，不能广播凭据或个人信息。宿主收到通知后清除自己的业务缓存与在途请求。UI 的实例内 generation 不能替代浏览器 Cookie 顺序验收。
