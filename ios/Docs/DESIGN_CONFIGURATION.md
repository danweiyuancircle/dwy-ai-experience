# 组件库配置与使用规则

日期：2026-11-12。状态：第二版配置契约；首批实现与验证见 `ios/Docs/UI_FOUNDATION_IMPLEMENTATION.md`，未实施部分不作为当前公开能力。

## 1. 默认即能使用

新项目选择 `DesignKitIOS` 或 `DesignKitMac` 后，使用本端标准主题即可构建页面。默认风格、交互、状态和布局由平台规范决定，应用不需要先填写几十个配置项。

根配置只承载真实产品差异，常见页面的圆角、阴影、主次按钮和输入框样式由库维护。主题注入本身不做网络请求、注册全局快捷键、申请权限或持久化用户数据。

## 2. 配置的所有权

| 配置 | 默认/所有者 | 允许的覆盖 |
|---|---|---|
| 标准视觉与组件尺寸 | 对应平台设计库 | 产品用标准默认；已成立的密度/尺寸档通过公开场景选择，不逐页传像素 |
| 强调色与品牌资源 | 产品品牌配置 | 应用根统一覆盖；资源内容通过原生 Label/图片槽，不在组件内部查应用文件名 |
| 系统/浅色/深色偏好 | 用户与应用装配 | 复用已有 ThemeManager/ThemeMode，保留应用现有存储键和用户值；不新增第二套主题中心 |
| 字号与可访问性 | 系统优先，产品已有设置补充 | 内容可增长，不允许强制关闭 Dynamic Type、减少透明度/动态效果或增加对比度 |
| 文案与本地化 | 产品文案及库自身资源分别负责 | 保留 LocalizedStringKey / LocalizedStringResource 或 Text/Label builder；用户原文/已解析 String 明确区分，库文案使用所属 target 的资源 |
| 按钮主次/危险/禁用/忙碌 | 调用处根据真实状态提供 | 使用标准语义参数和原生 role/disabled；页面不能自己覆盖危险色去隐藏风险 |
| 材质场景 | 平台规范与局部区域 | 内容、浮动操作、系统工具栏等有明确含义的场景；不允许任意玻璃透明度组合 |
| 菜单/表单/确认的宿主 | 产品场景/窗口 | 显式提供来源与动作，库负责本端呈现约束；不能全局找首个窗口代替真实来源 |
| 触觉偏好 | iOS 产品 | 只在适用交互注入策略；库不读取 ADBox remote.haptics 或自建产品偏好键 |
| 设备、账号、服务、授权、缓存 | 业务与既有领域模块 | 不进入设计主题；通过业务组件明确接口连接 |

全局主题不负责功能开关。AI、账号同步、购买、日志采集等是否开放由应用版本范围和业务配置决定。

## 3. 作用域

1. **应用/scene 根**：标准主题、品牌与实际偏好；每个独立窗口都装配，不隐式继承另一个 NSHostingView 的环境。
2. **页面/区域**：仅选择已定义的材质/密度/呈现场景，例如 Mac toolbar 和浮动动作组。
3. **组件**：标题、Label、Binding、动作、真实状态及已定义变体。
4. **业务**：校验、提交、权限、请求、持久化和错误来源。

公开组件使用 E 前缀；两端分别导入 DesignKitIOS / DesignKitMac，再使用 `EButton`、`EPicker` 等类型。根主题通过 `.eControlTheme(...)` 注入，区域材质通过 `.eControlPlacement(...)` 选择。同名类型保持各端独立契约；不因命名统一而同时导入两端模块。

禁止按页面重新定义整套品牌或复制 token 值。局部特例确有必要时先说明用途和受影响组件，不把临时外观覆盖升级为全局默认。

### 本地化契约

- 便利初始化器不能先把可本地化字面量全部收为 String，再期待 Text 自动提取。UI 文案使用受支持的 LocalizedStringKey / LocalizedStringResource 或 Text/Label builder，保留 locale、bundle 和插值信息。
- 用户输入、日志内容、设备名等原文按 verbatim 语义展示；已由业务显式解析的 String 可以传入，但不冒充自动本地化入口。
- 库自身文案从所属 target bundle 解析，优先使用最低维护工具链支持的机制；不硬编码 main bundle，不强推旧工具链不支持的宏。参数、数量、日期、列表使用资源插值/原生格式化，不拼接句子。
- 独立消费工程同时验证 App 与库资源、语言切换、带参数文案、长文本和可访问名称，不能只检查一段固定中文。

### Environment 与数据流契约

- theme、placement、size 是稳定的值配置；自定义 Environment/FocusedValue 键不存闭包，包进 struct 也不能解决闭包比较问题。组件动作通过参数传递，openURL/dismiss/refresh 等使用系统 Action 类型。
- 不在 @Entry 默认值中反复分配业务模型或服务；日志、帧、进度等高频更新留在读到它们的局部视图，不进入全局主题。
- 不将缺少 Equatable 单独视为缺陷：值类型可逐字段比较，Equatable 是优化路径。对自有状态明确观察粒度、稳定 ID 与主线程/生命周期要求，再以实际更新行为验证。
- UIKit/AppKit UI 边界与可观察 UI 状态明确 MainActor 隔离；纯数据配置不持有应用服务。双端共享模块不因此引入任一平台的窗口生命周期。

## 4. 页面开发规则

- 组件已覆盖的按钮、选择器、输入、反馈、表单等优先用公开组件；系统原生控件可在规范允许的组合中直接使用，例如 Menu 内的 Button/Toggle。
- 页面负责布局和业务，引用语义间距/排版，不重复实现玻璃、圆角、边线、hover、按压和禁用效果。
- 原生系统拥有的外观不重新仿制；DatePicker、系统文件面板、认证品牌按钮等不为“统一”而重画。
- 自定义画布、图表、遥控方向盘等保留专用实现，记录其为何不能用基础件。不要把遥控 key 类型引入 DesignCore。
- 不对整个应用根强制套一个 ButtonStyle 覆盖菜单/工具栏/所有业务交互；样式按组件与区域集中处理。
- 不用 Gesture 替代普通 Button 来绕过原生行为；复杂手势需要独立的可访问和键盘设计。
- 页面不按系统版本选择组件内部材质；iOS 18/26 的差异由 DesignKitIOS 处理，Mac 26 直接用适用 API。

## 5. 输入、状态与错误

- 文本绑定保留用户输入；字数限制、IP/端口/命令校验留业务边界，不在输入控件里自动补默认值。
- 选择器使用强类型 Binding 与稳定选项身份；候选移除不能悄悄选第一项并触发业务写入。
- `isBusy` 表示真实任务状态；库显示并限制重复动作，但不自行启动任务、重试、吞异常或决定成功。
- 取消按钮只在任务确实可取消时提供；取消、失败、pending 与成功有独立结果。
- 简短成功提示可以非模态；需要用户处理的错误使用可持续阅读的合适呈现。普通提示不能让整个工具栏永久禁用。
- 对外部数据、文件和网络输入保留必要验证。业务组件抽取时验证与错误处理不能丢失，也不在每层重复兜底。

## 6. 产品接入与迁移

- App 只选择对应平台 UI 产品；双端共享业务代码不依赖某一端 UI。ADBox 当前无条件导出 DesignKitIOS 的结构需要先修正。
- 接入使用已发布的固定版本或提交；示例/本地验证可以引用本地源码，但本机路径和临时镜像不进入业务工程提交。
- 先通过本地薄适配保留旧组件名和业务参数，再逐页切换；桥接只转参数和组合，不能保留另一套样式实现。
- 每迁移一种组件，同时检查所有实际调用方和代表性入口。隐藏或未发布的业务不因组件抽取恢复。
- 新项目模板必须展示标准主题和代表性组件的接法，并依赖包含这些 API 的实际发布版本。

## 7. 配置变更与发布

- 新增 public 配置需说明真实使用场景、默认行为、影响范围与验证，不能把内部实现细节全部暴露出去。
- 新品牌配置不改变全局业务语义；默认主题改变会影响所有使用者，需要视觉变更说明与回归。
- 旧配置迁移保留用户设置，不批量重命名或清空 UserDefaults/Keychain。
- 公共接口、默认 tokens、规范、示例和测试同步更新；版本兼容影响按仓库现有发布规则处理。

## 8. “新项目可复用”的验收

分别生成一个全新 iOS 和 Mac 项目，只使用公开产品与标准主题，完成：表单输入、选择绑定、操作/菜单、加载/空/错误状态与一个真实动作回调。随后只改品牌配置，检查全部组件同步变化且交互不变。

全过程不引用 ADBox、没有复制旧组件、不手改组件内部源码、没有逐页拼同一套外观。iOS 最低 18 与当前最新支持大版本（相关场景保留 26 引入节点）、Mac 26 按平台矩阵验收后，才能标记完整交付。
