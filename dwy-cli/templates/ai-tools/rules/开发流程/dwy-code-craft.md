# 编码大局观

写代码不是完成这个函数，是让这个 Feature 六个月后还能改。
可维护 = 改一处全处对，不是提前设计未来。可扩展 = 新需求落成新文件，不是到处留钩子。

分层规则管包边界；本文件管「这一份代码怎么长」。

## 一、动笔前四问

写之前在思考里过完，不必问用户。答不出 → 先搜再写。

1. 这段代码属于哪一层、哪个 Feature？
2. 同 Feature 里有没有同类页 / 同类接口？
3. 这次需求会让哪几处**一起变**？
4. 同类需求再来一次：是**加新文件**，还是给这堆 `if` 加分支？

## 二、五条行文

| 原则 | 判定 | 禁止的误读 |
|---|---|---|
| **第二次才抽** | 同一 UI 骨架 / 同一业务规则出现 ≥2 次才抽；1 次保持原地 | 第一份就抽 `BaseXxx`、`useCommon` |
| **扩展 = 加新文件，不改旧文件** | 新页面、新字段、新状态应能新增，不必改已有页面 | 预留 `options` / plugin / `if type ===` 大开关 |
| **先找同类，再写这一份** | 写前同 Feature 内搜列表/表单/详情，对齐结构；80% 相同抽组件或 composable，20% 用参数/slot | 每页从零写一套表格+筛选+分页 |
| **按「为什么会改」拆** | 筛选条件变了不该动列定义；权限变了不该动请求封装 | 一个文件里塞请求、表格、弹窗、权限、格式化 |
| **复制允许，分叉必须收口** | 第一份可以照着抄；第二份会出现且会一起改 → 本轮就抽 | 「先复制五份以后再整理」 |

## 三、屎山预警

出现任一条：**停手拆，不准继续往上堆。**

- 第三份复制
- 一个文件混了 ≥3 种变化原因（请求 / 表格 / 弹窗 / 权限搅在一起）
- 用 `type` / `flag` 区分本该是新文件的行为
- 在已经难读的文件末尾再追加大段逻辑
- 跨 Feature 直接 import「图省事」（升层 / Protocol / 壳编排，见对应 `dwy-*-layering`）

## 四、自进化

两环，**不改本文件**。项目私货写 `project-rules`，不往全局准则里追加。

| 环 | 何时 | 做什么 | 不做什么 |
|---|---|---|---|
| **任务内收口** | 本轮会变成第 2 份重复，或正在改的文件因本次变更更乱 | 本轮抽/拆完才能说做完 | 不顺手重构无关文件 |
| **仓库自成长** | 同类屎山/坑 ≥2 次 | 写入 `project-rules`（现象 / 根因 / 怎么避免） | 一次性问题不立条 |

发现本 Feature 已有更好结构：新代码跟那个结构；抽出时把旧的那份一并收口。禁止发明第三套风格。

## 五、和「简单优先 / 精准改动」共存

| 借口 | 现实 |
|---|---|
| 「先写完以后再抽」 | 第 2 份出现就是抽的时机，本轮做完 |
| 「用户只要这个页面」 | 要的是可维护的页，不是又一座孤岛 |
| 「和精准改动冲突」 | 为消灭重复而改第一份，算本需求，不算「改进相邻代码」 |
| 「先留 options 方便扩展」 | 扩展靠加文件，不靠预留钩子 |
| 「这是简单优先」 | 简单 = 少概念、短路径；不是复制五份 |

红线仍在：大重构、换架构、清理无关死代码，仍须用户明确要求。

## 六、行为变更与测试位置

行为变更（新功能、修 bug、会改变可观察行为的重构）先写失败测试，再写实现。文案、注释、Markdown、CI 配置直接改。

- 测试放独立目录并镜像源码：`src/foo/bar.ts` → `tests/foo/bar.test.ts`；Python 用 `tests/test_*.py`。禁止把测试和 fixture 写进业务 `src/`。
- Android 用 Gradle 测试源集 `src/test/`、`src/androidTest/`，与 `src/main` 分开，这是合规写法。
- 上面没覆盖的栈：独立测试目录 + 镜像源码 + 该生态主流 runner。栈内目录细则见对应 `dwy-*-testing`。
- 改完只跑受影响的测试。改了公共 fixture 或 `conftest.py` 就全量。提交前不要求全量，全量留给 CI。
- 基础库的 `TEST_CASES.md` 跟测试目录走（`tests/TEST_CASES.md`），和测试文件一起改。

## 七、提交前检查

- [ ] 四问过完，同类已搜过
- [ ] 没有新增第 2 份未抽取的重复
- [ ] 没有用 flag/type 把本该新文件的行为塞进旧文件
- [ ] 正在改的文件没有因本次变更更难拆
- [ ] 踩同类坑 ≥2 次已写入 `project-rules`
- [ ] 行为变更先有失败测试，测试不在业务 `src/` 里
