# 商用开源依赖许可合规（强制）

> 销售、SaaS、付费 App、对外交付的商业产品引入开源库时，
> 许可不合规会带来版权/违约风险。本规则约束：选型禁区 + 强制署名时的声明义务。

## 一、适用边界

- **适用**：任何面向收费/销售/对外商用的应用（含内部先试用后商用的产品）
- **不适用**：纯学习/练手/未商用的 builder 原型（一旦要上架/收费，必须补齐本规则）
- **覆盖栈**：npm/pnpm、PyPI/uv、CocoaPods/SPM、Gradle/Maven、ohpm、pub、Docker 基础镜像、字体/图标/素材、模型权重与 SDK
- **声明范围**：仅 **直接依赖**；不强制盘传递依赖

## 二、核心原则（三条）

1. **先查许可，再装依赖** — 未确认 license 的包禁止引入
2. **明确不可商用 / 强 copyleft → 禁止直接使用** — 换可商用替代，或购买商业授权
3. **仅当许可强制要求署名 / NOTICE 时**，才在隐私协议附录中声明（含版本）；**不强制署名的库不必写**

## 三、禁止引入（不可商用 / 高法律风险）

以下类型**默认禁止**写入依赖树（直接依赖必须查；已知会把禁区 license 顶进运行时链接的包也不得引）：

| 类型 | 常见标识 | 原因 |
|---|---|---|
| 明确非商业 | `CC-BY-NC*`、`CC-NC`、`PolyForm-Noncommercial`、许可证写 Non-Commercial / No Commercial Use | 商用即侵权 |
| 强传染 copyleft（闭源商用） | `GPL-2.0`、`GPL-3.0`、`AGPL-3.0`、`SSPL` | 可能强制整包开源或限制网络服务形态；**闭源商用一律禁止** |
| 限制竞争/生产用途 | `BUSL`（未到 Change Date 且限制 Production）、Commons Clause、部分 Source-Available | 表面开源，实则禁商用或禁竞争 |
| 仅免费个人/评估 | 字体/图标/SDK 写 "free for personal use only"、"evaluation only" | 商用需买授权 |
| 无 license / 自定义模糊条款 | 仓库无 LICENSE、或 "all rights reserved" 却当开源用 | 默认不可用 |

### 例外（必须显式记录）

- 已购买**商业授权**且合同覆盖当前用途 → 可引入，记录授权方、合同编号、到期日
- LGPL 等边界许可 → 不得默认通过，须单独评估后再定

### 选型动作（强制）

引入新依赖时在选型对比中增加一列 **License**，并标注：

- `OK-商用`（可商用；若无强制署名义务则声明页可不写）
- `OK-商用+强制署名`（MIT/BSD/Apache-2.0/ISC 等要求保留版权与许可声明 → 须进隐私协议附录）
- `OK-商用+额外义务`（如 Apache NOTICE、MPL 文件级 copyleft 等 → 按义务处理，署名类进附录）
- `禁-不可商用/高风险`（上表）→ **不得推荐为默认项**

## 四、强制署名时的声明义务

### 4.1 何时必须声明（仅此场景）

直接依赖的 license **明确要求** attribution / copyright notice / NOTICE / 保留许可文本时，必须声明。

**不强制署名则不写**：无保留声明义务的可商用库，不必塞进隐私协议或开源列表。

### 4.2 声明落点

- **唯一约定落点**：隐私协议 **附录**「第三方开源组件」
- 不与个人信息处理条款正文混写；附录与正文分节
- 若产品另有「关于 / 法律信息」页，可链到该附录，不替代附录本身

### 4.3 每条声明最低字段（强制）

| 字段 | 说明 | 示例 |
|---|---|---|
| 组件名 | 直接依赖包名 | `axios` |
| 版本 | **实际锁定版本**（lockfile / 构建锁定） | `1.7.9` |
| 许可证 | SPDX 标识 | `MIT` |
| 版权声明 | 来自 LICENSE / 包元数据 | `Copyright (c) 2014-present Matt Zabriskie` |
| 许可全文或链接 | 全文或稳定 URL | `https://opensource.org/licenses/MIT` |

**版本必须写锁定版本**，禁止只写 `latest` 或不写版本。

### 4.4 声明模板（可直接贴进隐私协议附录）

```text
附录：第三方开源组件

本产品直接使用的、且许可证要求保留声明的开源组件如下：

1. axios 1.7.9
   License: MIT
   Copyright (c) 2014-present Matt Zabriskie
   https://github.com/axios/axios/blob/v1.7.9/LICENSE

2. dayjs 1.11.13
   License: MIT
   Copyright (c) 2018-present, iamkun
   https://github.com/iamkun/dayjs/blob/v1.11.13/LICENSE
```

仅列 **直接依赖 + 许可强制署名** 的项；无强制署名义务的直接依赖不列。

### 4.5 何时更新声明

- 新增/替换直接依赖，且其许可强制署名
- 已声明组件的主版本或锁定版本变更
- 发版前：附录中的版本 vs lockfile **必须一致**；已移除的组件从附录删掉

## 五、执行检查清单（引入依赖 / 发版前）

- [ ] 直接依赖均有明确 SPDX license（或等价官方许可文本）
- [ ] 无 NC / 非商业 / GPL / AGPL / SSPL / 评估版字体图标等禁区
- [ ] 无未评估的 LGPL / 商业授权到期风险
- [ ] 仅对「许可强制署名」的直接依赖写入隐私协议附录（含版本号）
- [ ] 不强制署名的库未滥写进附录
- [ ] 附录版本与 lockfile 一致

## 六、AI 行为约束

- 推荐开源方案时：**必须带 license 与商用结论**（OK / OK+强制署名 / 禁 / 需商业授权）
- 候选为 NC / GPL / AGPL / SSPL / 无 license：**不得作为推荐默认项**；列出可商用替代
- 生成/修改隐私协议时：扫描直接依赖，**只把强制署名的项**写入附录「第三方开源组件」
- 不得以「业界都在用」跳过 license 核查
- 不得把无强制署名义务的库整表刷进隐私协议

## 七、常见许可速查（非穷尽）

| SPDX | 商用闭源 | 是否强制进隐私协议附录 |
|---|---|---|
| MIT / ISC / BSD-2/3 | 可 | **是**（要求保留版权与许可声明） |
| Apache-2.0 | 可 | **是**（保留 NOTICE / 声明） |
| MPL-2.0 | 通常可 | 按义务；修改过的 MPL 文件另有开源义务 |
| LGPL-2.1/3.0 | 须单独评估 | 评估通过后再定声明 |
| GPL / AGPL / SSPL | **禁** | —（不得引入） |
| CC-BY-NC* | **禁** | —（不得引入） |
| 无 license | **禁** | —（不得引入） |
