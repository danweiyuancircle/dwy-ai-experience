# SwiftUI 弹层与锚点

- 需要指向入口的 `popover` 或可能以 popover 呈现的 `confirmationDialog`，把呈现修饰符关联实际触发按钮或行；列表须对应当前目标，工具栏须对应入口。自定义锚点时检查其坐标和所属视图。
- 呈现方式由平台、系统和窗口环境决定；普通系统通知、居中 alert 等不一定有入口锚点，不按弹出位置错误处理。
- 在相关平台验证触发入口、滚动或窗口变化、屏幕边缘、取消和实际目标；以目标系统的交互及视觉为准，编译通过不能证明位置正确。
- 平台差异分别见 `dwy-ios-development` 的弹窗参考和 `dwy-macos-development` 的弹窗参考；这些 Skill 不可用时查 Apple 官方文档。

## 模态弹框的输入隔离

- 页面上的模态弹框（含自定义页内弹框）从打开到关闭完成，必须独占其模态范围内的用户输入。鼠标点击、右键、滚轮、触控、触控板手势、拖拽、键盘输入和业务快捷键不得穿透到底层页面或控件，底页不能因此触发按钮、菜单、选择、滚动、导航或数据操作。
- 明确页面级、窗口级或应用级的模态范围，覆盖该范围内的工具栏、菜单命令与页面事件监听；底页的事件监听和快捷键处理不得在弹框显示时继续执行业务动作。系统保留快捷键、弹框自身的输入法及辅助功能保持可用；窗口级模态不无故阻断其他独立窗口。明确设计为非模态的浮窗不套用独占规则，不能仅凭外观或使用 `popover` 就判断模态性。
- 优先复用符合所需范围的平台原生模态机制或已有共享承载。自定义承载须统一处理命中拦截、焦点和命令路由；仅提高层级、绘制透明拦截层或禁用底页命中，不能作为键盘与快捷键已隔离的证明。拦截输入不要求给底页加暗色或模糊蒙层。
- 展示时将焦点移入弹框，Tab / Shift-Tab 及辅助功能导航不得进入被阻断的底页，Enter / Space / Escape 只执行弹框约定的动作。底页原有输入焦点不得继续收字；关闭后恢复到仍有效的触发入口或页面合理位置。存在多层模态时，仅最上层响应，关闭后交还下一层。
- 外部点击按约定消费或用于关闭弹框；同一次点击、手势及其后续释放事件不得再激活底层控件。关闭动画结束前仍保持隔离，关闭后移除拦截并恢复正常输入。
- 验收须实际打开弹框，尝试点击底页按钮、右键、滚动、拖拽、输入文字、Tab / Shift-Tab、Enter / Space / Escape 及底页业务快捷键，确认底页无动作、无状态或数据变化，弹框内操作仍正常；再验证关闭点击不穿透、焦点恢复、底页操作恢复，以及实际存在的多层弹框和多窗口边界。iPad 外接键盘、鼠标与触控板按项目支持范围验证；截图或编译通过不能代替事件验收。
