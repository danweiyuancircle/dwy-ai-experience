# iOS 设计规范与组件复用

- 团队新 iOS 应用统一接入 AppleAppKit 的 `DesignKitIOS`，先核对已发布版本、Package.resolved、实际 checkout 与公开接口，不能引用本机源码路径作为正式依赖。App、扩展、独立 scene 按实际使用链接产品并在各自根装配 `EControlTheme`；`ThemeManager` 仍只管理用户明暗偏好。既有项目按授权范围迁移，不因启用本 Skill 自动升级依赖或全量改写页面。
- 基础库已有的按钮、输入、选择、表单、卡片与反馈必须复用，不在项目复制同功能实现。项目 UI 层可组合设备卡、业务表单、权限展示与品牌主题，通过值、Binding、Text/Label 和动作回调接入；设备、账号、权益、持久化和任务所有权留在项目业务/装配层。禁止为每个 E 组件再建同功能包装，禁止业务基础层反向依赖 UI。
- 原生 NavigationStack/NavigationLink、TabView、List、toolbar、sheet、alert、分享与文件选择保留系统契约；Menu/Picker 的内部条目与系统认证品牌控件继续用原生或认证模块。不以“统一组件”为由机械替换所有 Button、重绘导航或认证品牌按钮。确有缺口时记录具体能力与调用场景，按架构 Skill 判断补基础库还是保留项目专用组件。
- 设计规范应写清默认主题、语义 token、组件变体和状态、输入/选择的绑定契约、可访问性及目标系统矩阵；项目文档保存具体品牌与默认值，Skill 只保存平台约束。
- iOS 与 Mac 可以共用已成立的语义和纯数据契约，触点、排版、导航、键盘与弹层呈现按平台实现。iOS 库不能为共用外观而引入 AppKit 或 Mac UI 产品。
- 使用布局参考中的 pt、安全区、容器相对布局及三档宽度验收。原型尺寸不应变成页面固定宽高；长文案、Dynamic Type、iPad 尺寸类别与输入法属于组件契约。
- Menu 动作与 Picker 选值分开；保留原生 ButtonRole、Binding、tag、焦点与输入。组件不读取产品单例、持久化业务偏好、猜测成功或接管应用路由。
- 公共文案保留原生可本地化类型或 Text/Label builder，用户原文与已解析 String 分开；库资源使用所属 target 的 bundle。Environment 和本地化实现按可用的 Apple SwiftUI Skill 查证，不把回调或高频任务状态放进全局主题。
- 通用组件的版本分支、原生玻璃、减少透明度和动态字体适配集中在 `DesignKitIOS`；项目表达操作层级和 `eControlPlacement`，不在页面复制 `.glassEffect` / `.glass` 样式分支。内容卡不默认玻璃化，系统导航不重复叠材质。项目专属绘制确需新适配能力时先核对库接口，不用任意 View 包装器绕过边界。
- 已有遥控器方向盘、镜像控制等业务专用图形可保留项目适配，须记录具体文件、业务理由与验证边界；自动检查按项目的明确例外清单放行，禁止用宽泛目录豁免新增通用重复实现。空业务模板没有这类例外，不据此要求既有业务页面全部零玻璃 API。
- 展示、行为测试与最低/当前最新支持系统的实际交互分别验收；影响玻璃时覆盖 iOS 26 引入节点。模板的 `python3 -m unittest discover -s Tests -p 'test_*.py'` 检查版本、平台依赖、主题装配和通用材质边界，不能替代编译、语义审查和设备验收。候选或原型不标为稳定复用组件；基础库更新后各应用须更新锁定版本、重新构建并验证自己的入口。
