# Mac 设计规范与组件复用

- 先核对项目采用的设计规范、基础库产品及锁定版本。组件满足需求时必须直接复用。抽取时按架构 Skill 区分通用控件、可复用业务与应用窗口状态。
- 规范应明确默认主题、语义 token、主次/危险/忙碌状态、键鼠路径、焦点/窗口归属和可访问性；具体配色与尺寸由项目/基础库文档维护，不硬编码进通用 Skill。
- Mac UI 独立于 iOS UI 产品。共用语义不等于共用手机布局；优先原生 controlSize、toolbar、Menu、Picker、NSWindow/NSPanel 行为。系统已有玻璃背景的区域避免重复叠加材质。
- 控件保留原生 ButtonRole、Binding、键盘与可访问名称。尺寸明确区分字形和命中；忙碌时保留名称，危险语义不被品牌 tint 覆盖，focus 与 selected 可共存。
- 公共文案保留原生可本地化类型或 Text/Label builder，库资源使用所属 target 的 bundle。主题使用稳定值配置；Environment、本地化与更新策略按可用的 Apple SwiftUI Skill 查证，不把闭包或高频业务更新塞入全局主题。
- 自绘建议框、popover 和确认呈现需验证滚动裁剪、窗口移动/缩放、屏幕边缘、首次点击、焦点恢复与取消；平台窗/应用生命周期留明确宿主，不由通用控件查找全局首个窗口。
- 已采用 DesignKitMac 的项目，已有且满足需求的通用页面、表单、行样式和平台对话框直接使用共享入口，禁止逐个再套同功能包装或复制实现。需要业务语义、产品样式或交互组合时，在项目 UI 层的 `BusinessUI/`（或既有同职责目录）封装业务基础组件，优先组合共享组件；不存在或不足以支撑业务效果的部分允许用 SwiftUI/AppKit 自行实现，并收敛到对应业务组件中，不散写到页面。不必等到跨 Feature 复用才封装，也不提前创建无需求的包装。
- `BizFoundation` 保持纯逻辑，不放业务 UI；组件通过值、Binding 和动作回调接入。共享组件的通用主题和系统适配仍由基础库负责，自行实现部分由项目验证系统适配、键鼠、焦点与可访问性。通用缺口按真实复用收益和改动成本判断是否回流，不强制先补库。系统 API 可以留在组件内部，任务、授权与危险操作的业务语义不能随展示层迁走。
- 独立示例只验证公开产品的可用性；最低系统、产物最低版本/架构和实际应用窗口仍分别验收。设计候选与原型不标为稳定组件；不因共享控件升级修改用户数据、全局隐私设置或产品业务权限。
- 已采用 DesignKitMac 的项目，通用页面、表单、行样式、文本样式和平台对话框必须走满足需求的共享入口。实际缺口按前述业务组件和回流规则处理。文本用 `EText` / `.eText(_:tone:)`，不裸写 `.font(.caption)` 或 `.foregroundStyle(.secondary)`；具体禁止清单见 `dwy-apple-appkit` Skill。任务、授权与危险操作语义保留在业务。
- AppleAppKit 0.12.0 起，macOS 模板和 `DesignKitMac` 默认使用 `.standard` 的冷静蓝、明暗灰阶和 13 pt 正文。应用有品牌或密度需求时，从标准主题改相应角色并在窗口或子树注入 `.eControlTheme(theme)`。组件读 `@Environment(\.eControlTheme)`，静态令牌仅反映标准主题。改强调色须同时验证 `onAccent` 在浅色、深色和增加对比度下的可读性。
- AppleAppKit 0.13.0 起，共享业务页面可选用 `BusinessKitMac` 的设置面板、购买、帮助反馈、文件保存分享、快捷键、评分、账号与同步入口。应用提供自定义页面、商品、偏好保存与权限策略。设置面板可装入原生 `Settings` window 或 `.sheet`。接口以所选版本的 `apple/Docs/Mac-Business-Kit.md` 为准。
- macOS 菜单式 `EPicker` 从 AppleAppKit 0.13.1 起支持 `selectedLabel`，用于按选中值布局收起按钮。长文案可设置 `maxLabelWidth`，菜单项保持完整文案与原生单选勾选。
