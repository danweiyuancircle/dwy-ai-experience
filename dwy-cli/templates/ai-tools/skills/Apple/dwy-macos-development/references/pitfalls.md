# macOS 踩坑

记录已验证的 macOS 专属问题；每条写现象、适用系统与条件、根因及证据、处理方式、验证状态和未验证项。先查重；未证实的推断不能写成事实，项目专属问题留在项目中。

## macOS 15 原生外观与 Liquid Glass

- 现象：系统组件在 macOS 15 上可以呈现原生外观，但这不能证明使用了 macOS 26 的 Liquid Glass API。
- 依据：曾有项目通过系统导航和表单完成 macOS 15 样式适配，源码未使用玻璃 API；当时目标系统的完整视觉交互验收尚未完成。
- 处理：分别检查 API 实际使用与目标系统的显示、交互，不以构建或签名通过替代验收。

## 其他应用全屏时，菜单栏图标有反馈但菜单未展开

- 现象与范围：在 macOS 27.2.1 上，用户在 Warp 的原生全屏空间点击 RightFlow 状态图标时，图标高亮但菜单未出现。
- 排查：分别验证「图标点击后菜单是否展开」与「选中命令后业务窗口是否出现」。前者查状态栏菜单的呈现路径，后者查窗口激活、目标 Space 和焦点。图标高亮只说明点击有视觉反馈，单凭这一点无法确认窗口层级或系统根因。
- 处理：RightFlow 的设置、退出等简单命令改由 `NSStatusItem.menu` 持有的 `NSMenu` 展开，选中设置后再激活业务窗口。若业务需要自定义面板，核对实际宿主的 `NSWindow.collectionBehavior`、窗口层级、所属屏幕及焦点。提高窗口层级无法替代 Space 验收。
- 验证：在普通桌面与另一个应用的原生全屏空间分别点击真实图标，确认菜单可见、Escape 可关闭、取消不会切换 Space，再验证选择设置时窗口出现。支持多屏时分别检查状态图标所在显示器。RightFlow 签名构建、路由测试和设置快捷键已通过，真实全屏状态栏点击仍待复测。
