# 共享与抽取

1. 查项目已有模块、团队基础库、实际调用方与依赖版本，优先复用可满足需求的能力；不能把抽取候选当作已存在的能力。
2. 区分跨产品基础能力、跨 Feature 的本产品业务能力和某个平台的壳或界面状态，按职责及依赖方向确定落点。
3. 多个实际入口的行为与约束相同且存在重复实现时，应合并为公共入口并同步调用方；根据收益、接口稳定性和迁移成本确定最小落点，不默认上升到跨产品基础库。一次性业务留在原处，不为假设复用提前建层；界面与操作复用同时遵循 `dwy-swift-development` 的团队写法。
4. 共享逻辑只抽真正相同的部分；平台生命周期、窗口、导航和平台专属状态留在对应端。改基础库与业务侧修复按实际成本、复用收益及授权判断。
5. 验证现有调用方、公开接口、依赖边、受影响平台和测试。跨仓库修改、破坏性接口变更、新增依赖或发布须有相应授权。

通用缺口本轮落在业务侧时，遵循项目关于基础库抽取候选的记录和确认规则；不自行扩展本轮范围。
