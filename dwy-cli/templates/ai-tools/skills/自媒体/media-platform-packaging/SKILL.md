# 多平台自媒体包装与封面

把内容的核心承诺变成可点击的标题和手机缩略图。目标不是把大纲塞进封面，而是让观众先读到「谁能看懂 + 这集讲什么」。

## 在 uc-media 流水线中的位置

| 项 | 内容 |
|----|------|
| **stage** | `packaging`（**0090，可选**） |
| **何时** | 0070 成片包就绪后，或用户说「要发了 / 写标题封面」；可与 0080 并行或在 render 后 |
| **上游** | 脚本/成片承诺、`0060-assets` 视觉、频道档案默认分发 |
| **产出目录** | `{work_dir}/0070-package/`（包装清单 + `cover/`） |
| **不替代** | 0020 标题候选（可吸收 ★ 标题再按平台改写） |

## 输入与输出

先阅读用户提供的文章/视频稿和项目内的视觉资产、角色设定。按以下优先级找视觉资产：当前集 `media/0060-assets/` → 当前集 `remotion/public/characters/` → 仓库 `shared/characters/`、`shared/backgrounds/`。若素材不足，基于正文作合理假设，不为一般创作阻塞追问。

默认交付：

1. B站、抖音、小红书各一组标题、简介、标签。
2. 三种画幅的封面：B站 16:9、B站首页 4:3、小红书/抖音 3:4；用户只指定部分平台时只做所需画幅。
3. 各平台**建议发布时间**（UTC+8）：默认按 `references/platform-posting-times.md`；有账号后台「粉丝活跃」数据时以后台为准。
4. 一份写入 `media/0070-package/` 的包装清单，列出文案、建议发布时间与资产路径。

若用户只要求“文案”“标题”“封面方案”或“几点发/发布时间”，只交付对应内容；不生成图片、不要求 `imagegen`，也不创建包装清单，除非用户明确要求保存。

## 平台文案规则

| 平台 | 标题策略 | 简介与标签 |
|---|---|---|
| B站 | 主题 + 明确收益；长度不强行压缩 | 用开场问题、内容范围、一个边界或收获；4–7 个 `#标签` |
| YouTube | 主题 + 明确收益；长度不强行压缩 | 用开场问题、内容范围、一个边界或收获；标签字段使用多个关键词，并以**英文逗号**分隔，例如 `AI education, large language models, Transformer` |
| 抖音 | 问题或反常识钩子优先 | 1–2 句，强调观看收益；3–6 个标签 |
| 小红书 | **必须不超过 20 个汉字（标点计入）**；先写“小白也能懂”或直接收益 | 2–4 句，口语、可保存；5–8 个标签 |
| 微信视频号 | **必须不超过 16 个字符（中文、英文、数字与标点均计入）**；优先“人群 + 主题/收益” | 1–2 句，直接说明看完能获得什么；3–5 个标签 |

避免“保姆级”“秒变专家”“全网最全”等空泛承诺。标题、封面主字和简介可以分工，不能机械重复。

## 最佳发布时间（提高播放量）

完整规则与测试方法见 `references/platform-posting-times.md`。包装交付时必须给出建议时间表；原则摘要：

| 平台 | 工作日首选（UTC+8） | 周末首选 | 备注 |
|---|---|---|---|
| B站 | 17:00–18:30、20:00–21:30 | 10:00–12:00、20:00–22:00 | 高峰前 30–60 分钟发；知识区偏晚间 |
| 抖音 | 07:00–08:30、18:00–20:00、21:00–22:30 | 10:00–12:00、20:00–23:00 | 小号可避 19 点整，改 12:15 / 21:00 |
| 小红书 | 07:00–09:00、11:30–13:00、19:00–22:00 | 09:00–11:00、20:00–21:30 | 万粉以下慎挤 19–21 大号墙 |
| 微信视频号 | 07:00–09:00、12:00–13:30、18:30–21:00 | 10:00 前后、20:00–22:30 | 发后 15 分钟内互动，喂社交裂变 |
| YouTube | 按目标观众时区 | 目标市场白天 | 中文受众可用北京 19:00–22:00 |

约束：

- 时区默认中国 UTC+8；YouTube 必须先确认目标市场。
- **本号后台粉丝活跃曲线 > 本表默认值**。
- 多平台同日分发时错开 15 分钟以上，优先保 1–2 个主平台黄金窗。
- 包装清单中写清「建议时间 + 一句话理由」；无后台数据时标注「默认窗，待校准」。

## 封面版式：先缩略图，后信息密度

每张封面只允许一个绝对主标题；看不清时删减，而不是加字。

### 固定视觉母版

`assets/cover-style-master-v1.png` 是本 Skill 的封面视觉母版。生成封面时应先将它作为 **style reference**，并保留以下不可变特征：

- 深海军蓝底、亮黄与白色超大主字、红色漫画爆炸框、青蓝/紫色发光概念装置；整体必须高对比。
- 主标题占据左侧或上方 40% 左右，粗深蓝描边 + 白色外轮廓 + 明确投影；手机缩略图中先读到主标题。
- 小圆以右侧或下侧大脸近景出现，黄色雨衣、蓝绿背包、惊讶/恍然表情，动作指向核心概念装置。
- 画面仅有：一个主标题、一句钩子、一个概念装置、最多三枚底部承诺标签；不加入密集流程图、细小图标或说明文字。

这是“强标题科技漫画”风格，不是普通扁平信息图或复杂技术海报。生成后必须以约 25% 缩放预览检查：标题仍清楚、人物表情仍可辨、核心概念仍一眼可见，才可交付。

1. **主标题**：占画面 35%–50%，两行以内；用“`小白看懂` + `主题`”或“`主题 + 关键问题`”。
2. **概念装置**：只选择一个可以看懂的核心隐喻，不画完整课程流程图。
3. **系列人格**：使用项目规定角色；脸部或动作要大，服务主标题而非抢字。
4. **内容承诺**：最多三个小标签，例如“Transformer｜训练三步｜会聊天”。
5. **钩子**：可加一个顶部短问句/爆炸框；仅一句。

画幅重排，不裁切：

| 画幅 | 优先构图 |
|---|---|
| 16:9 | 左侧大标题，右侧角色 + 概念装置；底部可放三枚标签 |
| 4:3 | 标题与角色更靠中央，角色脸部放大，四边保留 7% 安全区 |
| 3:4 | 上方问题 + 巨大两行标题；下方概念装置 + 角色近景；底部标签不超过三枚 |

推荐最小导出尺寸：16:9 为 1920×1080；4:3 为 1600×1200；3:4 为 1080×1440。生成后必须核对实际像素比例。

## 生图流程

**REQUIRED SUB-SKILL:** 使用 `imagegen` 生成或编辑封面；先读取它的 `SKILL.md`。

1. 检查本集/项目已有角色和风格图；有既定角色时，把它作为 reference image。没有时，不擅自创造长期角色设定。
2. 为每个画幅分别生成，提示词中明确 `true 16:9`、`true 4:3` 或 `true 3:4`，禁止“裁切横图”。
3. 生成前写清楚所有需要出现的文字；文字过多时把复杂信息移进小标签。若生成文字失真，重新生成或留出干净文字槽位后用后期排版，不交付乱码。
4. 生成后检查：画幅、标题可读性、角色一致性、手机尺寸下的第一视觉、无水印/品牌 Logo/多余文字。
5. 不覆盖既有素材；保存到 `media/0070-package/cover/<主题>-<平台>-<画幅>-vN.png`。
