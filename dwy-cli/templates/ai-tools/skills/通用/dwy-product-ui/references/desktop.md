# 桌面端：窗口、键盘与系统协作

用于桌面客户端及相关宿主行为，按实际操作系统应用。网页渲染内容另读网页端规范；平板仅借用适用的窗口尺寸与键盘原则，不继承桌面应用退出、菜单栏或文件窗口语义。

## 窗口与布局

- 布局适应产品支持的窗口宽度、缩放和显示比例。侧栏、列表、详情与工具栏按空间调整，不能依靠锁死窗口大小掩盖布局问题；保留合理的最小尺寸及已有窗口约束。
- 沿用系统和项目已有标题栏、菜单、工具栏及窗口控件。可拖动区域不吞按钮、文本选择或辅助功能；无边框窗口等已确认设计保留同等可用性，不为换皮重做窗口管理。
- 桌面信息密度可以更高，但主次和可读性仍清晰。表格、分栏、快捷操作用于真实任务，不把所有内容放进居中的窄手机卡片，也不为铺满大窗口新增虚构内容。

## 焦点与输入

- 复用目标系统的焦点顺序、菜单和快捷键约定。弹窗在正确窗口或文档上下文展示，关闭后焦点返回合理位置；未激活窗口不抢输入，后台刷新不无故抢焦点或激活应用。
- 快捷键按目标系统和当前焦点处理，不能破坏编辑、复制粘贴、输入法组合文本或系统命令。菜单项与按钮调用同一业务动作，不维护两套结果不同的实现。
- hover、右键和拖放可以提高效率；必要功能仍能通过键盘或明确操作入口到达。混合触摸设备按实际支持补充触摸行为，不给纯桌面界面强套移动端密度和导航。

## 窗口与任务生命周期

- 区分关闭弹窗、关闭文档或内容窗口、结束后台任务和退出应用。具体语义以目标系统、产品约定与当前实现为准；不能在共享关闭回调中无差别退出进程或结束其他窗口任务。
- 多窗口的选中项、编辑内容、加载和错误反馈归属正确窗口；聚焦已有窗口与创建新窗口按产品规则执行，不能因共享状态误操作另一窗口。
- 影响编辑或文件操作时，沿用已有保存、取消和未保存更改处理。关闭、退出与失败均不能静默丢数据；不因本次只改页面就擅自引入托盘、后台驻留或新的退出策略。
- 平台惯例分别核对：macOS 的菜单、文档窗口和应用生命周期按其规则；Windows、Linux 的窗口与系统集成按各自已有实现。不能把某个平台“关闭最后窗口”的策略设成所有产品通则。

## 本次验收

在目标桌面系统运行受影响页面。布局变更检查相关窗口尺寸、长内容和缩放；输入变更检查焦点、输入法与已有快捷键；窗口或任务变更再验证打开、激活、关闭及必要的多窗口隔离。

局部颜色、对齐或文案修改不要求重测整个应用生命周期。网页内容验证与宿主窗口验证分别报告；网页截图不能证明原生菜单、窗口或退出行为正确。
