# 网页端：浏览器、语义与响应式布局

用于浏览器和客户端内的网页渲染内容。手机或平板浏览器组合移动端的尺寸、触摸和软键盘规则；桌面容器只有涉及宿主窗口或系统能力时才应用相应桌面条目。

## 浏览器行为与语义

- 导航使用链接，执行动作使用按钮，输入有持久标签，数据关系使用合适的结构；优先原生语义和项目已有组件。不要靠可点击容器和临时 ARIA 拼出已有控件的焦点与键盘行为。
- 保留正常链接的新标签页、复制地址和修饰键点击行为。需要分享、刷新或前进后退恢复的筛选、分页与详情使用已有路由机制；局部瞬时状态不机械写入 URL，更不把敏感值写入地址。
- 浏览器前进后退与页面内部返回含义一致，恢复任务所需位置与条件。刷新后如何加载按真实入口处理；不增加无关缓存或自动持久化来掩盖路由问题。
- 保留浏览器缩放、文本选择、粘贴和密码管理器能力。表单遵循已有提交约定，不能把输入法确认或多行文本换行误当提交，也不对所有输入机械绑定同一快捷键。

## 自适应与可访问性

- 根据可用视口与内容调整布局，不能只按设备名称或固定屏幕宽度选模板。移动浏览器地址栏、键盘和滚动会改变可见区域，固定底栏、弹窗与提交按钮必须仍可访问。
- 桌面指针可有 hover 增强，但触摸与键盘不依赖 hover。焦点清楚可见，弹窗正确进入、限制和恢复焦点；使用已有组件行为，只有模态范围限制焦点，普通页面不锁死 Tab。
- 文字放大和浏览器缩放后内容仍可用。长内容、窄视口、表格和代码区各自处理溢出；可横向滚动的数据区域有明确边界，不让整页意外横向移动。
- 纯图标控件有可访问名称，动态错误和状态按语义可被辅助技术感知。图片提供合适的替代文本，装饰图片不重复朗读；有主题和动效时尊重目标浏览器的系统偏好。

## 加载与性能

- 异步内容和媒体预留合理布局空间；首屏主要内容不过度依赖入场动画。加载时保留页面上下文，错误有可用恢复路径，不把加载中的列表先展示为空。
- 输入响应、长列表和动画以实际数据和目标浏览器验证；按测量选分页、懒加载或虚拟化。优先已有高效布局与动效实现，不用固定条数或统一耗时口号代替测量。
- 涉及服务端渲染时，保持初始内容和输入稳定，避免恢复阶段丢焦点、丢输入或明显跳动；纯客户端页面不增加不适用的服务端流程。

## 本次验收

用实际页面入口在目标浏览器操作。按改动检查相关视口、长内容、缩放、键盘、加载与错误；路由变化再测直达、刷新、前进后退，表单或移动布局变化再测软键盘和触摸。

桌面浏览器的窄视口只能辅助检查布局；不能代替手机浏览器的软键盘、动态可见区域或系统返回验证。只检查产品实际支持且本次影响的浏览器与宿主，不扩展成无关兼容矩阵。
