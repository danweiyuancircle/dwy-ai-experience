# 移动端：手机、平板与触摸场景

按目标系统、窗口与实际输入方式选用。原生导航与系统控件条目用于移动客户端；手机浏览器页面组合使用网页端规范，只采用这里的布局、触摸、软键盘及文字适配原则。

## 布局与输入

- 以当前可用窗口尺寸组织内容，尊重安全区、系统栏、挖孔和手势区域。背景可按平台惯例延伸，主要文字、按钮和输入不能被遮挡；复用框架的安全区与键盘处理，避免多层重复加偏移。
- 软键盘弹出后，正在编辑的字段、校验信息和主要操作仍可访问；允许滚动到达下一步。合理配置输入类型、提交键、自动填充和收起方式，不强抢焦点，不强制使用与输入内容不符的键盘。
- 触摸区域、控件密度和间距遵循目标平台及项目规范。必要操作有可发现的点击入口；长按、滑动或 hover 不承担唯一入口，系统手势区域不布置冲突操作。
- 原生界面遵循系统文字缩放与语义样式；网页保留浏览器文字与页面缩放。长文本可换行，放大后容器随内容调整，不通过固定高度裁掉标签或把字号缩回去。
- 平板、折叠屏和多任务窗口按实际宽度重组列表、详情和导航；不能把手机页面等比例拉宽，也不能仅靠设备型号决定结构。只验证产品已支持且本次受影响的窗口和姿态。

## 导航与系统行为

- 移动客户端沿用目标平台的导航栈、返回与关闭方式。进入子页、完成独立任务、关闭弹层和切换主区域的语义保持清楚，不把系统返回一律改成退出或回首页。
- iOS/iPadOS 复用系统导航、表单与弹层惯例；Android 复用现有系统返回处理和适用的预测性返回行为。跨平台框架保留各目标系统的行为差异，不能为外观统一复制另一系统的导航和图标。
- 输入中断、切换页面、后台返回或提交失败时，按本次流程保留必要上下文。只在保存成功或用户明确放弃后结束编辑；不为此额外保存敏感输入或新增无需求的持久化。
- 权限说明在用户触发相关能力时就近出现；拒绝后按真实可用能力提供下一步，不假装成功，也不在每次打开页面时重复阻塞。
- 平板使用外接键盘、指针或辅助功能时，保留系统提供的焦点和快捷键行为；不能因为是移动设备就假定只有触摸，也不手写覆盖系统已有的键盘导航。

## 本次验收

先走本次改动涉及的用户任务；表单检查键盘出现、收起和错误恢复，布局检查相关窄窗口、长内容或文字放大，导航检查返回与取消。旋转、分屏、主题和后台恢复仅在产品支持且本次可能受影响时补测。

原生界面在目标系统的模拟器或设备中验证，手机网页在目标浏览器验证；浏览器预览不能证明原生导航、键盘或生命周期正确。无法运行的部分明确标注，不以构建成功代替界面验收。
