# 子代理派发与长任务续接

## 先判断收益和依赖

复用宿主已有的子代理、消息和状态能力，不引入新调度框架。工具未提供这些能力时由主代理执行，不假装已派发。简单任务直接完成；独立查询先考虑工具批处理；独立且工作量足够的任务再派发。并发数服从宿主实际容量和资源条件，不为占满名额而派发。

| 工作 | 并行条件 |
| --- | --- |
| 独立文档调研、调用链追踪、不同根因的日志分析 | 各自可独立产出，范围明确；没有共享写入。 |
| 不同模块开发 | 接口和行为契约已确定，文件归属清楚，配置、锁文件、数据库及构建资源不会互相干扰。 |
| 测试与验证 | 测试数据、端口、设备、缓存及构建目录可独立使用；争用可写资源时串行或使用项目已有隔离方式。 |
| 独立审查 | 被审查快照稳定，只读且上下文独立；审查时仍被修改的范围必须在集成后重新审查。 |
| 契约设计、公共配置、依赖锁、数据库迁移、集成与部署 | 先明确责任人与顺序；不能因文件不同就默认可并行。共享工作区的 Git 写操作由主代理统一执行。 |

先解决依赖链上的前置任务，再派发后续实现。没有接口契约时，可以并行调研，不能让各模块自行猜接口。遵守项目分支和工作目录规则，不为并行擅自另建分支或 worktree。主代理可同时推进独立工作，不重复子代理正在做的同一任务。

## 派发最小上下文

每个子任务说明以下内容，缺少的信息由主代理先查证或明确为待调查项：

- **目标与验收**：本任务需要交付的具体行为与检查，关联总目标的哪一部分。
- **范围与归属**：准确的仓库和工作目录、可改文件、只读范围、已有改动；不得覆盖其他人的修改。
- **输入与契约**：相关需求、项目规则、入口位置、接口约定、当前快照和已确认事实；使用路径和定向摘录，不倾倒完整日志与历史。
- **依赖与资源**：前置任务、共享资源及其责任人，是否需要等待；涉及环境时写明实际目标，不由子代理自行切换环境。
- **执行边界**：允许读写、可执行的检查及原任务授权范围；子代理不因收到任务而获得额外外部操作权限，也不自行递归派发。
- **返回内容**：结论、实际改动路径、检查命令与结果、阻断或待决策项；较长产物放文件并返回路径，原始日志只保留定位问题所需片段。

默认新建独立上下文并传上述信息。只有任务确实依赖难以准确摘取的历史决策、且宿主支持时才继承必要历史；继承的是启动时的上下文，不代表后续自动同步。它不会删除主代理已有上下文，也不保证降低总 token 消耗；节省来自把后续探索和执行细节留在子代理侧。

审查任务传需求、规则、代码快照与验证证据，不传开发者自我评价。主代理接收摘要后按风险核实关键代码、接口和证据；不能仅凭子代理说「通过」就判定整体成功，也不必重复读取全部日志。

## 协调与集成

- 用户的新要求由主代理解释并检查影响，尽快通知受影响的子代理；接口或范围改变时让旧任务暂停相应修改，更新契约后再继续。旧契约下的产物不能直接合入。
- 子代理发现需要修改其他责任人的文件、公共接口或共享配置时，报告具体依赖，由主代理协调归属与顺序；可独立完成的部分继续，不私自扩大修改范围。
- 共享工作区的修改即时可见，不能把“完成”消息当作代码才开始出现的时间。集成前核对在途任务和实际差异，避免测试读到尚未完成的修改。
- 子任务完成后按依赖顺序集成，检查冲突及调用方，再验证最终组合的代码。子任务测试通过不能替代集成验收；沿用主 Skill 的持续修复和交付标准。
- 主代理持续处理交互。用户询问状态时简要回答后继续；纠正和约束同步到相关任务，只有明确取消或替换目标时才放弃原目标。

## 长任务的最小状态记录

多阶段、可能跨会话或有较长等待的任务，复用项目已有计划或任务记录；没有约定时写入 `.dwy/tasks/<task-id>/progress.md`。短任务不额外建状态文件。

只记录可恢复执行所需的信息：目标与验收条件、最新接口决策、子任务状态和责任范围、产物路径及对应快照、已执行检查和结果、当前阻断与下一步。代理标识或后台进程只作为定位线索，不记录凭据或整段会话。

在阶段完成、接口或需求变更、出现阻断以及交接时更新记录。恢复时先读记录，再核对实际工作目录、代码、环境、代理与后台任务状态，确认哪些产物和检查仍有效；已经完成且仍有效的工作不重复做，失效部分重新验证。不假设宿主会在会话结束后继续运行代理、自动唤醒或自动恢复；不具备持续运行能力时留下明确的下一步并如实说明。
