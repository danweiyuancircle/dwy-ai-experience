# 子代理派发与长任务续接

## 先判断收益和依赖

复用宿主已有的子代理、消息和状态能力。按可独立验收的产出拆分，同一工作需要的语言、框架、架构和基础库 Skills 由负责人按需一起读取。轻量查询可直接做或用工具批处理。有明确收益时，尽早派发已具备条件的工作，主代理继续推进独立事项。宿主缺少派发能力时由主代理完成普通调研和实现，独立审查遵循 [主 Skill 第 4 步](../SKILL.md#4-执行审查)。

| 阶段 | 可独立派发的工作 | 依赖与约束 |
| --- | --- | --- |
| 调研 | 按需分别查需求原文与验收、官方工具与权限、已有实现与项目经验。需求和工具分别用 `dwy-project-requirements`、`dwy-tool-discovery` 的适用部分；同一能力需要另选依赖时，由技术调研负责人按 `dwy-open-source-selection` 接续评估。 | 代理回传事实、出处和未决项。主代理统一定范围和契约，再派依赖这些决定的实现。 |
| 实现 | 按前后端、平台或独立模块分派。涉及日志时，负责人一并应用 `dwy-logging-privacy`。 | 接口和行为契约已定，文件归属明确。共享配置、依赖锁和迁移链各有一名负责人。 |
| 验证 | 按模块或目标平台跑检查，设备、端口、测试数据、缓存和构建目录可独立使用时并行。 | 同一资源按顺序使用，或按项目已有方式隔离。汇合后验证最终组合，独立审查基于实际待交付快照。 |
| 交付 | 按需并行核对版本来源、固定 diff 和发布准备。已有并行脚本或 CI 时复用其调度。 | 共享工作区的 Git 写操作由主代理统一执行。迁移、部署和发布明确责任人，按依赖和授权推进。 |

例如开发管理端分页列表，先约定字段、分页、权限与错误响应，再并行实现 Python API 和 Vue 页面，各自带测试。页面可先用约定接口的 mock，最后由主代理验证实际联调。子代理遇到契约缺口或共享文件冲突时，回报主代理决定涉及的接口和顺序，继续推进独立部分。

遵守项目分支、工作目录和专用 Skill 的调度规则，额外分支或 worktree 按项目规则和已有授权处理。并发数服从宿主实际容量和共享资源，主代理按需核查关键证据。

## 派发最小上下文

每个子任务说明以下内容，缺少的信息由主代理先查证或明确为待调查项：

- **目标与验收**：本任务需要交付的具体行为与检查，关联总目标的哪一部分。
- **范围与归属**：准确的仓库和工作目录、可改文件、只读范围、已有改动；不得覆盖其他人的修改。
- **输入与契约**：相关需求、项目规则、适用 Skill、入口位置、接口约定和当前快照；用路径和定向摘录交接，子代理自行读取相关资料。
- **依赖与资源**：前置任务、共享资源及其责任人，是否需要等待；涉及环境时写明实际目标，不由子代理自行切换环境。
- **执行边界**：允许读写、可执行的检查及原任务授权范围；子代理不因收到任务而获得额外外部操作权限，也不自行递归派发。
- **返回内容**：结论、实际改动路径、检查命令与结果、阻断或待决策项；较长产物放文件并返回路径，原始日志只保留定位问题所需片段。

普通派发默认使用独立上下文，只传上述信息。历史决策优先给简要结论和出处。确需原会话且无法准确摘取时，才按宿主能力继承必要历史；后续变化另行同步。资料展开、日志分析和实现细节留在子代理侧。

审查任务的交接和回传遵循 [主 Skill 第 4 步](../SKILL.md#4-执行审查)，使用独立上下文。

## 协调与集成

- 用户的新要求由主代理解释并检查影响，尽快通知受影响的子代理；接口或范围改变时让旧任务暂停相应修改，更新契约后再继续。旧契约下的产物不能直接合入。
- 子代理发现需要修改其他责任人的文件、公共接口或共享配置时，报告具体依赖，由主代理协调归属与顺序；可独立完成的部分继续，不私自扩大修改范围。
- 共享工作区的修改即时可见，不能把“完成”消息当作代码才开始出现的时间。集成前核对在途任务和实际差异，避免测试读到尚未完成的修改。
- 子任务完成后按依赖顺序集成，检查冲突及调用方，再验证最终组合的代码。子任务测试通过不能替代集成验收；沿用主 Skill 的持续修复和交付标准。
- 主代理持续处理交互。用户询问状态时简要回答后继续；纠正和约束同步到相关任务，只有明确取消或替换目标时才放弃原目标。

## 长任务的最小状态记录

多阶段、可能跨会话或有较长等待的任务，复用项目已有计划或任务记录；没有约定时写入 `.dwy/tasks/<task-id>/progress.md`。短任务不额外建状态文件。

只记录可恢复执行所需的信息：目标与验收条件、最新接口决策、子任务状态和责任范围、产物路径及对应快照、已执行检查和结果、当前阻断与下一步。代理标识或后台进程只作为定位线索，不记录凭据或整段会话。

在阶段完成、接口或需求变更、出现阻断以及交接时更新记录。恢复时先读记录，再核对实际工作目录、代码、环境、代理与后台任务状态，确认哪些产物和检查仍有效；已经完成且仍有效的工作不重复做，失效部分重新验证。不假设宿主会在会话结束后继续运行代理、自动唤醒或自动恢复；不具备持续运行能力时留下明确的下一步并如实说明。
