# 开发、审查与复用闭环

每次代码开发开始时加载，以功能成功交付为首要目标，自主完成开发、验证、审查与必要修复，再集中输出结果和确实需要用户确认的事项。识别架构、规范和模块边界问题，积累有证据的复用能力；允许结论为「无需抽取」。

本 Skill 只定义通用流程，不依赖特定 CLI、模型、语言、框架或其他 Skill。自动加载取决于宿主的技能发现能力；本文件本身不是强制执行器，也不授予额外权限。

## 入口与决策

- **开发任务**：从第 1 步走完整闭环，不把计划、候选方案或测试通过当作最终交付。
- **单独审查**：确认范围后直接进入第 4 步，不要求先开发或测试全绿。只读审查已有实现，说明验证缺口；用户未要求修复时不改代码。
- 根据需求、项目约定、已有实现及实际运行环境，自行决定常规实现、检查与排障方式。环境问题先检查现有工具、配置和可用替代，不将能自行解决的问题交还用户。
- 目标含部署时，核实已授权的目标环境、运行版本和部署条件，完成必要部署及运行时验收。持有凭据或发现可用服务器不等于获得部署授权；本地测试不能替代目标环境的功能成功。
- 已有授权覆盖的下一步直接执行，不重复询问。遇到无法安全推断的关键条件或确需额外授权的动作，先完成其余可独立交付的工作，再只询问该具体阻断；不能先执行越权动作再补确认。

## 1. 确定范围

- 读取当前项目规则、需求和验收条件，确认工作目录、分支与已有改动。纯分析请求只输出分析，不进入开发。
- 列出本次涉及的实现、调用方、测试、配置、迁移、导出和文档；无关文件保留原样。发现需求或授权边界不清时先解决该问题。
- 定义可验证的成功标准与简短步骤，先分析依赖和共享资源，再选择直接执行、工具批处理、串行派发或并行子代理；只有实际收益超过派发、通信、集成和返工成本时才拆分。
- 确认任务代码基线。有 Git 时核对基准提交及任务路径的现有差异，无 Git 时核对任务文件；后续新增、删除和未跟踪文件也计入范围。按审查指南决定记录粒度，不为小改动机械生成全套摘要。

多步骤任务有派发收益，或长任务需要阶段续接时，读取 [references/delegation-guide.md](references/delegation-guide.md)。主代理保留目标、接口决策、用户交互、集成及最终验收责任；子代理承担边界明确的执行工作。默认只传必要上下文、只回收摘要和证据；宿主支持且确需历史决策时才继承会话，后续变化另行同步。

## 2. 查找与开发

- 先检索项目已有实现、能力目录及复用候选，再查标准库、平台能力、已安装依赖及匹配工具；跨项目只检索已授权的仓库或目录，不扫描无关位置。核实候选的实际实现与版本，不能把待抽取建议当作现成能力。
- 按项目规则核实新工具的来源、权限、数据去向和维护成本；不因本 Skill 自动安装依赖、连接账户或上传代码。
- 按项目测试约定开发；缺陷修复先建立重现证据，非平凡行为补充有意义的测试。只实现本次需求，不为未来复用提前扩展接口。

## 3. 验证当前实现

执行项目要求的测试、类型检查、静态检查与构建；按影响范围选择检查，项目明确要求的检查不得省略。记录命令、结果、跳过原因及对应的任务代码快照。

检查后代码、测试或配置发生变化，相关旧结果失效。无法运行、超时和环境故障均记录为「未完成」，不能当作通过；区分源码、单测、真实设备、外部服务与部署验收。

## 4. 执行审查

读取 [references/review-guide.md](references/review-guide.md)，按其中的审查维度与输出契约执行。开发任务通常先完成必需检查；环境阻断验证时，仍完成可执行的审查，并将受影响验收项标为未完成，不伪造整体通过。

有可用且获授权的独立审查能力时，给审查者需求、规则、变更快照和检查证据，让其自行读取实现及影响范围，不传开发者的自我评价。否则重新读取最终代码进行自审，并注明自审。审查只读，不修改当前工作树、索引、分支或 HEAD；审查者不再递归启动审查者。

## 5. 修复与复审

- 主执行者先复核问题证据；已授权范围内的明确缺陷直接做最小修复。存在分歧时核对调用链或测试，不盲目接受建议。
- 修复后重跑受影响检查并复审变更及其影响范围。测试通过不能替代架构审查，架构建议也不能替代测试。
- 不按固定轮数停工；只要有明确可执行的下一步且持续取得进展，就自主修复、复测和复审直到满足验收。相同失败反复出现时根据证据调整方案，不重复无效尝试；只有排查后仍无法自行解除的外部阻断、额外授权或用户停止要求才中止相应工作，并报告真实状态。

## 6. 沉淀与交付

- 记录粒度按审查指南选择，优先使用项目既有位置。需要完整报告且没有约定时，写入 `.dwy/reviews/<task-id>/review.md`；有复用候选时更新 `.dwy/reuse-candidates.md`。`<task-id>` 使用本任务稳定的短标识，续跑复用原记录，不覆盖其他任务。
- 记录只绑定任务代码、测试和配置；更新审查记录本身不会使验收失效。无文件写权限时返回同样内容并注明尚未落盘，不宣称已沉淀。
- 候选先查重，保留来源与证据；迁移落地后更新能力目录的实际入口、调用方和验证结果，让后续任务能够检索使用。非本轮必需的抽取记录为后续候选，不阻塞功能交付。沉淀规则遵循项目现有约定，不擅自修改全局配置、个人记忆或无关项目。
- 只有当前任务快照的必需检查、审查及需求包含的目标环境验收通过，才报告功能交付成功。先完成已授权的实施与验证，再输出结果、环境证据、剩余限制，以及集中列出的交付验收确认或可选后续决策；能自行决定的事项不列为待确认，没有则写「无需额外确认」。
