# 页面开发：简洁、完整、一致的正式产品

页面围绕用户当前任务组织：必要内容、可用操作、真实状态。正式产品的质感来自清楚的主次、一致的组件、真实内容和完整交互。辅助文字只有在影响当前操作或判断时才进入主界面，留白不需要靠文字填满。

本 Skill 的正文是通用规范，分端资料补充运行环境的差异，均可离线执行；具体控件和实现遵循目标平台及项目已有规范。研究来源与取舍见 [references/design-baseline-sources.md](references/design-baseline-sources.md)，仅维护规则或核查依据时读取。

用户明确的视觉要求与项目设计规范优先；不借简化重设计页面、删减已约定功能或扩大为全项目改造。

## 先按上下文选择适用规范

开始修改前，从用户指定的页面、文件、截图、工程配置、实际运行入口和现有界面判断目标。分别确认运行环境、界面实现方式、窗口尺寸与输入方式；不能仅凭框架名或设备名推断平台。仓库有多个客户端时，只处理本次明确的目标；线索不足以定位页面时先澄清，不任选一个客户端开改。

通用正文始终适用，再按下表读取本次所需的分端资料，仅执行与改动相关的条目：

| 实际上下文 | 读取与应用 |
|---|---|
| 手机、平板上的原生或跨平台客户端 | [移动端](references/mobile.md)；按目标系统和输入方式应用 |
| 桌面客户端 | [桌面端](references/desktop.md)；按目标操作系统应用 |
| 浏览器页面 | [网页端](references/web.md)；在手机或平板浏览器中再组合移动端的尺寸、触摸、软键盘规则 |
| 桌面客户端内的网页界面 | 网页端用于渲染内容，桌面端用于窗口与系统交互；只改网页布局时不扩大到宿主生命周期 |
| 平板分屏、外接键盘或可调整窗口 | 移动端为基础；本次涉及窗口或键盘时补读桌面端相应条目，不照搬桌面应用的菜单或退出语义 |

同一框架可以承载不同终端，同一终端也可能同时使用触摸、键盘和指针。冲突时按该功能所在层的实际平台行为处理；已有平台 Skill 提供实现细节，本 Skill 负责页面质量，不要求迁移技术栈或安装研究来源。简述本次选择即可，不生成无关的平台清单或额外设计文档。

## 开发前：确定页面类型与已有规范

先确定本次页面的用途，再选择信息密度和表现方式；不把所有页面做成同一种模板。

| 页面类型 | 设计重点 |
|---|---|
| 操作型：后台、工具、设置、表单 | 扫描效率、内容与操作层级、熟悉的控件、状态反馈；不套营销首屏 |
| 阅读型：文档、帮助、教程 | 阅读顺序、正文宽度、标题和导航；保留理解任务所需讲解 |
| 营销或展示型：官网、活动、作品 | 真实品牌、素材和叙事；可使用明确要求的插画、渐变与表现性动效 |

读本次相关页面、调用链、组件库、主题 token 与平台规则，确认用户任务与实际状态。局部修改沿用已有视觉，只查影响范围；新项目先确定满足当前页面的最小字体、间距、颜色和组件用法，复用到同层级页面，不为此搭建额外设计系统。

将本次新增或调整的信息分配到以下位置；在工作分析中完成，不把这份分类写进产品页面：

| 位置 | 内容 |
|---|---|
| 主界面常驻 | 用户内容、明确标签、当前任务所需操作、会影响选择的真实状态 |
| 相关控件旁 | 输入格式和限制、权限用途、会改变操作结果的条件 |
| 对应状态中 | 正在处理、无结果、失败原因、恢复操作、必要的成功反馈 |
| 帮助或按需展开 | 低频操作方法、快捷键说明、详细机制；使用已有入口，确有必要才新增 |
| 开发记录或日志 | 实现细节、执行过程、调试信息、向开发者解释的设计理由 |

用户明确要求教程、引导或说明型内容时，按该内容的实际阅读任务设计，不机械套用操作页面的删减标准。

## 实现时：产品界面的共同底线

### 组件与视觉一致

- 优先复用项目组件、平台原生控件和已有成熟依赖。弹窗、菜单、选择器等复用完整的焦点与键盘行为；不为换外观手写一套交互，不在同一页面混搭行为不一致的组件体系。
- 同功能、同层级的按钮、输入框、图标、状态色和间距保持一致。复用主题 token，新增值须有当前布局或品牌依据，不逐页凭感觉创造字号、圆角和阴影。
- 优先用字号、字重、对齐和组间距建立主次。强调色服务主要操作、选中和状态；次要操作保持可见，不能靠低对比度降低竞争。数据比较保持数字对齐，日期和数值按目标语言格式化。
- 列表、表格、设置行和正文各用适合的结构。卡片表示独立对象、分组或操作边界，不给每段文字和每个筛选项套卡片；边框、阴影与背景不重复承担同一种分组作用。
- 操作型页面默认从内容和工具栏开始。不为“高级感”添加大幅欢迎区、装饰统计卡、渐变文字、发光或玻璃背景；已有品牌规范或明确视觉需求按其执行，不把某种颜色或效果列为跨产品禁令。
- 图标优先复用项目已有的成熟图标库或平台原生图标体系；项目没有时，查找并核实当前技术栈主流、成熟且持续维护的图标库，按项目依赖选型规则引入。功能图标禁止使用 emoji。
- 同层级图标保持来源、风格、线条粗细和实际视觉大小一致。按可见轮廓、留白、视觉重心及对齐效果检查，不能只凭相同的 width、height 或画布尺寸判断一致；此规则同样适用于 SVG、平台符号和图片图标。图标按钮保留可访问名称，不能靠图标或颜色单独表达风险和状态。

### 真实内容与完整操作

- 用已确认的字段、素材和数据设计。演示数据明确限定在示例或测试环境；不为填版面编造评价、指标、产品承诺或自动化能力，不将演示数据作为真实成功结果。
- 页面元素与能力对应：可点击的控件有真实动作，尚不可用的动作说明真实条件。不能用 toast 或假结果替代操作实现；也不因追求简洁隐藏必要入口。
- 按本次调用链覆盖加载、正常、空、失败及实际存在的权限或离线状态。等待时保留操作上下文，防止重复提交；失败保留用户输入，不能闪回空白页或要求无故重填。
- 列表或搜索进入详情再返回时，通过当前平台已有导航机制保留任务所需的筛选、分页和位置。不要为无关临时状态增加持久化。
- 表单有持久标签，允许粘贴及系统自动填充；校验不无故阻断正常输入。弹窗的焦点进入、关闭与返回符合平台约定，键盘焦点可见，危险操作可撤销或事先确认。

### 尺寸、动效与性能

- 以项目和平台尺度适配窄屏、宽窗口、安全区和文字放大。长名称、长邮箱、密集数据与本地化扩展不能挤掉操作；必要文本可换行或通过可访问入口查看全文，不靠缩字或整页横向溢出解决。
- 控件操作区域满足目标平台要求，必要操作支持当前平台的输入与辅助功能；固定栏和弹窗不能遮住焦点、输入或最后一项内容。
- 优先沿用现有动效；新增动效表达状态、空间关系或明确的品牌意图。使用平台或已有依赖实现，不为普通过渡加新库；不让入场编排、循环装饰或等待动画拖延操作，并尊重减少动态效果设置。
- 给图片、占位与异步区域保留合理空间，减少内容跳动；避免全屏模糊和大面积连续重绘。长列表根据实际规模和测量选择分页或虚拟化，不按固定条数强制加复杂方案。

## 文案：先决定要不要，再决定怎么写

### 辅助文案准入

对每条新增辅助文字，明确：**哪个用户，在什么状态下，缺少这句话会做错或无法完成哪一步？**

- 能从真实需求、已观察到的使用障碍或调用链回答：放到上表中最贴近该操作的位置。
- 只能回答“可能不知道”“显得专业”“让页面丰富”：不新增。
- 涉及业务行为但无法确认：先查实现；仍无法确认则指出缺口，不编造承诺。

常驻说明不得复述控件名称、标题或已有状态。同一状态、同一任务中的信息只表达一次；不同步骤各自必要的输入限制和风险提示可以在当地展示。

### 信息与交互

- 标签直接表达动作和对象，如“导出用户”；不另加“点击按钮即可导出用户”。
- 优先用清楚的名称、控件状态和合理布局表达交互。页面底部不堆“点击后会怎样”的常驻说明。
- 非显然且影响结果的行为，在操作前就近说明；低频技巧放帮助。必要信息不能只藏在临时提示中，要让目标平台的输入与辅助方式均可访问。
- 当前没有数据时，展示该状态和可用的下一步；不为填版面增加介绍、提示卡、统计卡或重复按钮。
- 设置项的名称已足以判断用途时，不强配副标题。名称不能表达的重要副作用或生效条件，就近补充，并以真实实现为准。

### 状态与错误

- 按真实状态分别呈现首次使用、未连接、无搜索结果、无权限和读取失败；不能统一写“暂无数据”。
- 故障发生时，说明失败对象、已知且有用的原因、可行的下一步；原因未知就不猜。失败提示留到问题解决或用户主动关闭，不以短暂 toast 代替阻塞错误。
- 输入限制在提交前可见；错误贴近相关输入。删除后果、支付条件、权限与隐私用途、不可逆风险必须在作出决定前可见。
- 执行日志不直接充当用户状态。“已读取设备状态”不值得常驻；实际未授权时，才显示对应的授权操作。
- 成功反馈与操作重要性匹配，不叠加 toast、横幅和底部状态重复报告同一结果。

### 简化的边界

只删除本次范围内的重复表达和无任务价值的装饰，不删除必要功能、校验、持久标签、无障碍名称或错误处理。不通过小字号、低对比度、截断或仅用图标隐藏必要文字。遵循平台字号与对比度要求，不设所有页面通用的字数、字号或提示数量上限。

## 交付前：产品完成度检查

1. **distill 检查**：辅助文字按文案准入问题判断，重复的合并，低频的移到合适入口；装饰和容器按页面类型、分组作用及明确的品牌意图判断，不套用文案准入问题。移走后保留必要信息的可达性，不增加一套无人需要的帮助系统。
2. **clarify 检查**：从用户入口走到结果，检查术语、动作、状态、后果和恢复路径；保留完整意义，不只追求短。
3. **一致性与完整性检查**：对照相邻页面，检查本次组件、视觉层级、真实内容、操作结果和受影响的失败路径；不能只验收默认状态截图。
4. **实际验证**：运行目标页面，按已选分端资料验证本次受影响的状态、尺寸、长内容和输入方式；有字体、主题或动效改动时，再检查相应系统设置。小范围文案或样式修改做对应显示与交互检查，不扩展成全平台回归。
5. **报告结果**：在交付回复中简述重要取舍及实际验证范围；不把验收说明加到产品页面。无法运行或无法构造的状态明确标注未验证，静态检查不等于视觉验收。

## 示例：设备管理页

未连接设备时，主区域显示“尚未连接手机”和已有的连接入口；应用区无需再重复整套连接提示。连接帮助保留版本、网络与授权要求。

“点击应用打开独立窗口，再次点击会聚焦原窗口；关闭只结束该窗口的画面”不作为常驻页脚：普通打开行为交给明确的入口表达，低频窗口规则放已有帮助。如果关闭会中断用户正在执行的任务，则按真实后果在关闭前就近说明。“已读取设备状态”留在日志；确实未授权时，在设备状态旁显示“请在手机上允许 USB 调试”。

反例边界：上传页的“PNG/JPG，最大 10 MB”和永久删除确认中的“删除后无法恢复”会改变用户选择，必须保留；不能因它们也是小字就删除。
