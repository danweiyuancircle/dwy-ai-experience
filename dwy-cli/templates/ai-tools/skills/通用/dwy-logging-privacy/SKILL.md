# 日志敏感信息约束

这是一条日志约束，不是日志设计方案。是否打印某条日志、记录什么内容、使用什么级别、格式和实现方式，均依据项目上下文、现有规则与排障需要决定，不由本 Skill 统一规定。

- **正式版暴露给用户的日志**：不输出敏感信息。适用于 iOS、Android、网页、桌面端等用户终端，覆盖用户可见或可获取的控制台、系统日志、本地日志文件和导出诊断日志。
- **Debug 和测试版本**：允许输出敏感数据，不因本约束删除或脱敏调试日志；这些输出不得在正式版用户终端生效。
- **内部后端日志**：本 Skill 不限制日志内容，也不要求过滤密码、验证码、密钥或会话凭据。后端日志若展示或导出给用户，暴露给用户的部分适用正式版约束；不因后端不受限而要求新增全量日志。
- **关键业务场景**：应保留有助于定位问题的日志，具体场景和输出内容依据项目上下文判断。不一刀切关闭正式版日志，也不要求每个操作、状态或字段都打印。

应用时结合项目的业务含义、字段来源、构建与环境配置、现有日志机制和实际调用链，判断数据是否敏感、代码运行在哪一端，以及输出在哪些版本生效。不仅凭字段名、日志级别或构建名称下结论；共享代码按实际运行位置分别判断。

发现项目现有规则或实现会让正式版向用户暴露敏感信息时，应提示用户，说明具体位置、受影响的输出、判断依据和调整建议；不能因为是项目既有规则就忽略。证据不足时说明可能性与不确定项，不把推断当作已验证事实。发现关键业务场景缺少日志、影响排障时，也结合实际调用链提示，不按固定清单要求补日志。

提示不等于获得修改授权。不因本 Skill 自动改写项目日志规则、删除日志或扩大采集；实际调整遵循用户授权与任务范围。

保留排障所需的信息，不吞掉异常。不规定必打字段、固定脱敏方式、关联标识、日志框架或检查流程，也不默认扫描和改造全项目。需要调整时复用项目现有机制，按实际影响选择必要验证，并说明未验证项。
