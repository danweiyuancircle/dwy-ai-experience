## 职责（单一）
识别 1 个核心技术死穴假设，写最小可跑 POC 实测能不能成。失败→建议砍方向/换技术栈，不进 PRD。

## 输入（从哪读）
- state.json 的 `confirmed.validation`（仅当 `pass=true` 才执行）
- `.dwy/prod/[项目]/01-立项/需求市场验证.md`、`想法收敛.md`

## 实现
[自写型]
1. 校验 `confirmed.validation.pass=true`，否则直接退出
2. 从想法中识别**唯一一个**最致命的技术假设（最可能让方案不成立的那个）
3. 写最小可跑 POC 代码实测，代码放 `.dwy/prod/[项目]/01-立项/poc/`
4. 实测结果定性：成立 / 不成立
5. 不成立 → 给出砍方向或换技术栈建议，**不进 PRD**

## 产出契约（硬约束）
- 落到：`.dwy/prod/[项目]/01-立项/技术验证.md`，POC 代码放 `01-立项/poc/`
- 固定章节：核心技术假设 / POC 方案 / 实测结果 / 结论与建议
- 回写 state.json：`confirmed.poc`（含 `pass` 布尔字段）
