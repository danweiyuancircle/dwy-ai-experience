# 网络与外部边界

先使用匹配的官方架构/测试 Skill。官方 HTTP 示例不要求已选 Dio 的项目换库；使用当前项目及共享包中已确认的方案。页面请求与 Widget 销毁的配合另按 `dwy-flutter-development` 处理。

## 客户端归属

- 网络基础包不依赖 Widget、路由或状态管理框架，业务接口、DTO 和 Repository 留在产品。
- 每个服务创建独立客户端，配置由 Assembly 注入。不要给云端 API、局域网设备或第三方图片域共用无边界的认证拦截器。
- 认证、刷新与响应解包是明确的宿主策略；不默认所有后端都返回 `{code,message,data}`，不在基础库中弹提示、跳登录页。
- 不把全部第三方 API 重写成另一套框架。基础封装统一实际共用的策略，必要的底层扩展入口标明绕过哪些 DWY 约束。

## 生命周期与数据完整性

- 配置连接、收发超时；区分超时、离线、HTTP 状态、解析失败、取消和本地文件失败，保留可诊断的原始 cause/stack。
- 请求取消与页面/业务任务生命周期绑定；关闭、切换仍等待临时文件、句柄和后台操作完成清理。
- 上传下载流式处理，进度使用真实字节；总量未知时不能伪造百分比。文件落盘不覆盖已有用户文件，临时内容与完整文件提交分开处理。
- 不默认重试写操作。确需重试或刷新后重放时，验证幂等性、请求体能否重新读取和请求归属，限制并发刷新及重试次数。
- 网络缓存、图片缓存、业务离线数据是不同责任；登录切换时按账户范围处理，不全局清理其他产品/账户的数据。

## 日志与验证

- 日志隐藏 Authorization、Cookie、Token、密码、签名 URL 参数及敏感正文；错误文本也属于输出边界，不能只脱敏正常日志。
- 不关闭 TLS 校验来解决本机网络问题，不吞异常伪造成功。
- 用本机 HTTP fixture 或可控适配器验证解码、HTTP 失败、超时/取消、进度和文件完整性；不以公共服务偶然成功替代边界测试。
- 共享库需验证关闭后的行为、取消清理，以及并发请求的作用域隔离；不能只测试包装方法被调用。
