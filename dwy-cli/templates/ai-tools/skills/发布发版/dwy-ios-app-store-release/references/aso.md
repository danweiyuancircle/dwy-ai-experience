# App Store 搜索优化

目标：提高名称、副标题、关键词被搜到的概率，并保住产品页转化。搜索流量主要来自索引字段，不是更新说明。

## 字数（按字符计，含中文一字）

| 字段 | 上限 | 每版本 |
|------|------|--------|
| 名称 | 30 | 继承后可优化 |
| 副标题 | 30 | 继承后可优化 |
| 关键词 | 100 | 继承后可优化 |
| 推广文本 | 170 | 继承；需更新时自改，不向用户询问 |
| 描述 | 4000 | 继承后可优化 |
| 更新说明 | 4000 | 后续版本必填；给用户读，不为堆词 |

## 索引权重

1. 名称
2. 副标题
3. 关键词（逗号分隔，逗号后不要空格）
4. 内购显示名

推广文本影响产品页转化，不作为主要索引。描述、更新说明对搜索贡献弱。

## 关键词

- 先列出名称 + 副标题已覆盖的词，关键词里不再重复，把 100 字留给新词。
- `zh-Hans` 与 `en-US` 各自选用户会搜的词，禁止英中一对一硬译。
- 优先：功能、场景、问题词。禁止竞品商标、无关热词、重复词。
- 现网已有关键词时：以现网词表为底，按本版新能力补漏、删无效词。禁止推倒重写。
- 首次：从产品能力生成候选，再压进 100 字。
- 交给用户确认前必须给出：旧关键词、新关键词、剩余字符数。

## 名称与副标题

- 名称：品牌 + 一个可搜的品类词（放得下才加）。
- 副标题：一句收益或场景，补名称没覆盖的搜索词。
- 已上架应用改名/副标题要展示现网对照；用户确认后才写。

## 推广文本

不向用户询问。

- 现网 `promotionalText` 有内容：原样继承。
- 与本版卖点明显不符（旧活动过期、主功能已换）：自行改写，改前可上网核对卖点、竞品表述是否仍准确。不要为改而改。
- 首次无现网：按名称、副标题、描述生成一句卖点，不要复述整篇描述。
- `zh-Hans` / `en-US` 各 ≤170 字；有现网底稿时保持双语都有内容。

## 禁止

- 把 `dwy-publish` 的 git `CHANGELOG` 塞进关键词或更新说明。
- 为冲搜索把更新说明写成实现细节或关键词堆砌。
