# 版本 tag

每个需要更新版本的工程，在版本来源和 changelog 完成后提交对应变更并打 tag。tag 的版本串必须与版本来源和 changelog 标题一致；tag 指向包含本次完整代码、版本和 changelog 的提交。遵循仓库既有命名，多个独立工程使用各自不冲突的 tag，已有约定优先。

打 tag 和推送前检查 tag 是否已存在、指向是否正确，以及推送是否触发 CI、发布或部署。推送由用户授权范围和项目要求决定；推送可能触发发布时，先完成测试、适用的安全检查及部署闸门，且仅在发布已获授权时推送。仅版本管理且推送会触发未经授权发布时，保留本地 tag 并报告。

部署新代码必须使用包含该代码的版本 tag 对应提交或其已验证产物；不能用旧 tag 掩盖新增代码。重发或回滚完全相同的已记录版本和产物，可复用原 tag，无须重复打 tag。不得未经用户明确授权删除或覆盖远端 tag / release。
