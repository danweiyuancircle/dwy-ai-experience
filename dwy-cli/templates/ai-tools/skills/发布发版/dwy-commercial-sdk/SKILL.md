# 商业 SDK 发布前检查

本 skill 适用于有商业保密或源码保护要求的 SDK，覆盖公开仓库、私有源和直接交付等分发方式。发版编排按项目约定执行；本检查不自行发布。

## 确定范围

1. 根据用户要求、项目文档、许可证、仓库公开状态、包配置和实际分发渠道识别 SDK、公开内容和需要保护的部分。不能根据“商业”二字推断源码必须保密；证据不足时询问用户。保护要求和交付范围存在歧义时先确认，再进行依赖该判断的检查。
2. 每次依据当前项目上下文判断，不创建或读取 `.dwy/sdk-spec/config.json`，也不修改用户的全局配置或凭据。

## 检查

- 检查公开接口、文档、注释及示例是否包含不应公开的内部地址、凭据、个人信息或实现细节；结合上下文判断误报，不输出完整秘密。
- 按确认的保护目标检查源码仓库、构建配置和分发渠道是否一致。编译、混淆和压缩只能提高还原成本，不能保证源码或算法无法恢复；公开仓库中的代码无法靠发布包配置保密。不要固定要求 Cython、minify 或排除所有源码。
- 检查实际拟交付的包或文件清单，核对源码、source map、调试文件、环境配置、凭据、许可证和运行必需资源是否符合交付范围。使用项目现有构建和检查工具；明确区分已有产物检查与实际发布产物验证。构建或打包前检查脚本副作用，不执行发布。
- 对发现的问题给出位置、风险、依据和修复建议；区分已验证、未验证和受环境限制的项目。按用户授权修复并重新检查，不把检查通过表述为绝对安全。
